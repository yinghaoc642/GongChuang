# 2026 省赛当前程序 version1 版本说明

> 文档版本：version1  
> 生成日期：2026-07-29  
> 当前主程序：`../src/main.cpp`  
> 适用对象：当前 STM32H750 省赛搬运机器人程序  
> 结论依据：当前仓库代码、2026 浙江省赛命题文件、2026 搬运初赛评分表，以及文件夹中的补充资料  

## 0. 先说结论：这套程序到底是什么

当前程序是一套“固定路线为主、局部视觉修正为辅”的完整比赛流程控制程序。

它能做的事情是：

1. 一键启动整套比赛流程；
2. 沿预先写死的 42 条路线命令行驶；
3. 用 IMU 在每段行驶或转向结束后修正车头角度；
4. 在二维码区读取并严格校验任务码；
5. 根据任务码决定两批物料的抓取颜色与圆环放置位置；
6. 在原料区通过视觉坐标调整机械臂抓取位置；
7. 在粗加工区和暂存区通过圆心视觉坐标微调底盘；
8. 控制 M5、M6、M7、夹爪和载物盘完成两批物料的抓取、放置、再抓取与同色码垛；
9. 在 HMI 上持续显示任务码、运行状态、抓取数、放置数、航向和电池电压；
10. 在部分硬件错误、通信错误或人工长按停止时进入故障状态并停机。

但它目前还不是一套能够完全适应 2026 省赛所有随机条件的自主机器人程序。它目前最关键的本质限制是：

- 底盘没有世界坐标 X/Y 反馈，位置依赖步进脉冲开环累计；
- 路线只支持启停区 1；
- 没有障碍物检测和避障；
- 原料区与二维码板虽然按规则可能改变位置，当前主路线仍按固定位置行驶；
- 当前仓库里缺少正式使用的 MaixCAM `vision-2.py`，只能确认 STM32 侧的视觉协议和处理逻辑，无法确认相机端真实识别算法；
- 圆检测协议只返回一个圆心坐标，没有返回 1、2、3 号圆环编号；
- 最终停车只按开环距离执行，没有真正的红外或视觉终点对齐，而且按代码累计的最终外廓可能没有完全进入启停区。

因此，更准确的评价是：

> 当前版本已经具有完整的比赛流程骨架、较成熟的非阻塞机械臂控制和局部视觉闭环，但全场定位、随机场景适应和最终安全闭环仍不完整。它适合继续做实车联调，不适合在未补齐高风险功能前直接认定为“省赛正式稳定版”。

## 1. 规则基线：本说明以什么资料为准

资料优先级如下：

1. `附件2-第十三届浙江省工创大赛-智能+工程创新赛道命题与运行（0710）.pdf`：2026 浙江省赛规则，最高优先级；
2. `2026搬运初赛评分表.docx`：2026 搬运任务评分项目；
3. `智能+赛道 解析.pdf`、`搬运地图带尺寸.png`：用于辅助理解场地；
4. 两份 2027 国赛 PDF：只用于参考未来趋势，不可覆盖 2026 省赛规则。

### 1.1 与当前程序直接相关的 2026 规则

- 场地尺寸为 2400 mm × 2400 mm；
- 中央十字车道宽度为 400 mm；
- 启停区尺寸为 300 mm × 300 mm；
- 颜色编号是：
  - 1：红色；
  - 2：黄色；
  - 3：蓝色；
  - 4：绿色；
- 任务码格式为：

```text
颜色组1+位置组1+颜色组2+位置组2
```

例如：

```text
134+123+314+231
```

总长度是 15 个字符。

- 正式流程是：

```text
启动
  → 读取任务码
  → 第一批原料区抓取三个物料
  → 第一批粗加工区按位置放置并重新抓回
  → 第一批暂存区平面放置
  → 第二批原料区抓取三个物料
  → 第二批粗加工区按位置放置并重新抓回
  → 第二批暂存区放到第一批同色物料上
  → 返回抽签确定的启停区
```

- 运行时间为 3 分钟；
- 要求一次按键启动；
- 机器人停止时间达到规则条件时可能被判定运行结束；
- 灰色道路上会设置位置随机的黑色障碍物；
- 二维码板和原料区位置存在现场随机性；
- 显示装置需要持续显示完整任务码以及抓取、放置统计。

### 1.2 为什么不能直接按 2027 文档改颜色

2027 国赛资料中颜色编号扩展到了 1～6，但 2026 省赛仍是 1～4。当前程序只接受 1～4，符合 2026 省赛，不能因为文件夹中存在 2027 文档就把校验范围直接改成 1～6。

### 1.3 评分角度需要特别注意的点

评分表的原始项目合计为 211 分，直接涉及当前程序的项目包括：

- 正确读取任务码；
- 每次正确抓取；
- 各工位正确放置；
- 正确返回启停区；
- 正确显示抓取统计；
- 正确显示放置统计。

当前程序中的计数是“动作状态机走完一次就加一”，并没有物料存在传感器、夹爪电流判断或视觉复核。所以程序显示的“正确抓取数”和“正确放置数”，严格来说只是“程序认为已完成的动作数”，不能证明裁判意义上的动作一定正确。

## 2. 机器人方向、世界坐标和车体方向

这是理解整个程序最容易出错的地方。

### 2.1 世界坐标

程序采用：

- 场地左下角为原点 `(0,0)`；
- +X 向右，也就是东；
- +Y 向上，也就是北；
- 单位为 mm。

示意：

```text
                         +Y / 北
                            ↑
        暂存区              │              二维码区域
                            │
      西  ←────────── 场地中心 ──────────→  东 / +X
                            │
                            │
                         粗加工区
```

### 2.2 车体四个侧面的定义

当前车体约定不是简单的“库里的 forward 就是车头”。

- 3、4 号轮所在侧：实际车头；
- 1、2 号轮所在侧：车尾；
- 2、4 号轮所在侧：机械臂、扫码器等伸出的一侧；
- 1、3 号轮所在侧：机械臂伸出侧的相反方向。

初始放在启停区 1 时：

| 车体侧面 | 初始世界方向 |
|---|---|
| 3、4 侧，实际车头 | 南 |
| 1、2 侧，车尾 | 北 |
| 1、3 侧 | 西 |
| 2、4 侧，机械臂侧 | 东 |

### 2.3 四种平移命令怎么理解

程序不使用“前进、后退、左移、右移”作为路线名称，而使用“向哪个车体侧面移动”：

| 命令 | 含义 | 运动学库中的方向 |
|---|---|---|
| `COMMAND_MOVE_SIDE_12_MM` | 向车体 1、2 侧移动 | forward 为正 |
| `COMMAND_MOVE_SIDE_34_MM` | 向车体 3、4 侧移动 | forward 为负 |
| `COMMAND_MOVE_SIDE_13_MM` | 向车体 1、3 侧移动 | left 为正 |
| `COMMAND_MOVE_SIDE_24_MM` | 向车体 2、4 侧移动 | left 为负 |

关键点是：

> 这些方向会跟着车体一起旋转。比如 `SIDE_24` 初始时是向东，但车体转过 90° 后，它可能变成向北、向南或向西。

所以看路线时，必须同时知道当前车体朝向，不能把某一个 `SIDE_xx` 永久理解成世界坐标中的东、西、南、北。

### 2.4 为什么程序说“位置是开环的”

程序会把“移动 1000 mm”换算成四个电机的目标脉冲。当前标定大约是：

```text
直行 1 m ≈ 10000 pulse
横移 1 m ≈ 10000 pulse
```

四轮电机安装方向修正为：

```text
[-1, +1, -1, +1]
```

程序知道自己“命令了多少脉冲”，但没有传感器告诉它“车体在场地上实际到了哪个 X/Y 坐标”。因此：

- 轮子打滑，程序不知道；
- 麦轮横移损失，程序不知道；
- 被障碍物碰偏，程序不知道；
- 地面摩擦差异造成少走或多走，程序不知道；
- 机械臂动作让车体产生微小平移，程序也不知道。

IMU只负责角度，不负责 X/Y 坐标。所以代码里的坐标是“设计坐标”或“按命令累计出来的推算坐标”，不是传感器实测坐标。

## 3. 硬件和通信接口

### 3.1 主控与执行机构

当前平台为 STM32H750，主要执行机构包括：

- M1～M4：麦克纳姆轮步进电机；
- M5：机械臂底座旋转轴；
- M6：机械臂伸缩轴；
- M7：机械臂升降轴；
- ID 4 串口舵机：夹爪；
- ID 5 串口舵机：车载物料盘旋转。

### 3.2 串口分配

| 功能 | RX | TX | 波特率 |
|---|---:|---:|---:|
| 调试串口 | PB12 | PB13 | 115200 |
| HMI | PB15 | PB14 | 115200 |
| IMU | PD9 | PD8 | 115200 |
| 二维码模块 | PE0 | PE1 | 9600 |
| MaixCAM | PE7 | PE8 | 115200 |
| M6/M7 串口步进驱动 | PA3 | PA2 | 115200 |
| 串口舵机 | PC7 | PC6 | 115200 |

其他关键引脚：

| 功能 | 引脚 |
|---|---:|
| M1 STEP / DIR | PD4 / PD6 |
| M2 STEP / DIR | PE11 / PE9 |
| M3 STEP / DIR | PD15 / PD14 |
| M4 STEP / DIR | PA1 / PC3_C |
| 四轮公共使能 | PE13，低有效 |
| 一键启动/长按停止 | PB9 |
| 电池电压 ADC | PC1 |

代码刻意没有使用默认 `Serial`，因为通用 H750 板型的默认串口 RX 可能占用 PA1，而 PA1 已经是 M4 的 STEP 引脚。

## 4. 软件整体架构

当前程序虽然集中在一个约 4300 多行的 `main.cpp` 中，但逻辑上可以分为 8 层：

```text
PB9按键 / HMI / 串口输入
          │
          ▼
程序总状态 PROGRAM_WAITING / RUNNING / FINISHED / FAULT
          │
          ▼
42条固定路线 RouteCommand 状态机
          │
    ┌─────┼───────────┐
    ▼     ▼           ▼
底盘命令  二维码动作   三类工位动作
    │                  │
    ▼                  ▼
四轮脉冲+IMU       MaixCAM+机械臂状态机
                       │
             M5 / M6 / M7 / 夹爪 / 载物盘
          │
          ▼
HMI状态、计数、调试日志、故障处理
```

### 4.1 为什么说主循环总体是非阻塞的

`loop()` 每次循环都依次服务：

1. 四个底盘电机的 `run()`；
2. M5；
3. PB9 按键；
4. IMU 接收；
5. M6/M7 状态；
6. MaixCAM；
7. 二维码；
8. HMI 航向；
9. 电池电压；
10. 急停；
11. 延时触发的载物盘动作；
12. 启动逻辑；
13. 工位机械臂状态机；
14. 总路线状态机。

大部分“等待”不是停在一个 `while` 循环里，而是记录当前阶段，然后在下一次 `loop()` 再检查是否完成。这使得电机运行、串口接收、急停和显示可以同时被持续服务。

这是当前程序最明显的架构优点之一。

## 5. 上电、启动和停止流程

### 5.1 `setup()` 上电初始化

上电后程序按大致顺序完成：

1. 初始化调试、HMI、IMU、二维码串口；
2. 初始化 MaixCAM 串口，并发送停止识别请求；
3. 等待 M6/M7 驱动器完成约 1500 ms 上电自检；
4. 初始化 M6/M7 串口；
5. 把 M6、M7 的当前位置在软件中直接定义为零点；
6. 使能 M6、M7；
7. 初始化夹爪和载物盘舵机；
8. 检查两个舵机是否在线；
9. 打开夹爪，把载物盘转到停车位；
10. 初始化电池 ADC；
11. 初始化四轮步进电机与 M5；
12. 把 M5 当前角度在软件中直接定义为 0°；
13. 绑定 PB9 短按启动和长按停止；
14. 初始化 HMI 页面与显示；
15. 清空二维码接收状态；
16. 进入 `PROGRAM_WAITING` 等待状态。

### 5.2 这里的“零点”不是自动寻零

这是非常重要的实车前提：

- M5 没有限位开关自动回零；
- M6 没有限位开关自动回零；
- M7 没有限位开关自动回零。

程序只是相信：

- M5 上电时确实处于规定的机械零姿态；
- M6 上电时已经完全缩回；
- M7 上电时已经处于最高位置。

如果上电时实际姿态不对，后面所有机械臂目标都会整体错误，并可能撞机构。

### 5.3 PB9 短按启动

短按 PB9 后：

1. 设置 `startRequested=true`；
2. 同时命令 M5 展开到旧坐标 -90°，也就是工位新坐标 0°；
3. 底盘不等待 M5 完全到位；
4. `beginRoute()` 先检查 IMU 是否有 600 ms 内的新鲜有效帧；
5. 检查 M6/M7 软件参考是否仍有效；
6. 清零路线下标、计数、动作标志和四轮软件脉冲位置；
7. 把当前 IMU 航向作为整场路线的 0°；
8. 打开夹爪，载物盘回停车位；
9. 使能底盘；
10. 进入 `PROGRAM_RUNNING`。

如果 IMU 尚未准备好，HMI 显示 `IMUWAIT`，车辆保持不动，但 M5 已经开始展开。

### 5.4 长按停止

运行中长按 PB9：

- 停止二维码扫码动作；
- 取消工位动作；
- 急停 M6/M7；
- 关闭底盘；
- 关闭 M5；
- 使 M6/M7 软件零点失效；
- 进入 `PROGRAM_FAULT`；
- HMI 显示 `STOP`。

停止或故障后不能直接把当前位置当作新起点再次比赛。程序要求断电、人工恢复 M5/M6/M7 标准姿态后重新上电。

## 6. 二维码逻辑

### 6.1 接收格式

二维码模块通过 9600 波特率串口发送 ASCII 字符，程序同时兼容：

- `\r` 结尾；
- `\n` 结尾；
- `\r\n` 结尾。

接收缓存为 32 字节，任务码必须正好是 15 个字符。

### 6.2 校验条件

一个任务码只有同时满足下面条件才有效：

1. 长度必须是 15；
2. 第 4、8、12 个字符必须是 `+`；
3. 两个颜色组三位字符都必须在 1～4；
4. 同一批的三个颜色不能重复；
5. 第一批与第二批必须包含完全相同的三种颜色，只允许顺序变化；
6. 两个位置组都必须恰好是 1、2、3 的一个排列。

有效后会解码成：

```text
taskColors[0][0..2]     第一批三个颜色
taskPositions[0][0..2]  第一批三个对应位置
taskColors[1][0..2]     第二批三个颜色
taskPositions[1][0..2]  第二批三个对应位置
```

### 6.3 到二维码区后怎么走

从启停区 1 先向实际车头方向走 1050 mm，到达开环推算的 `(2215,1200)`。

二维码串口在此前的行驶过程中也一直监听：

- 如果到点前已经获得有效任务码，不再额外前探；
- 如果还没有有效任务码，就以低速向车头方向最多前探 500 mm；
- 前探途中一旦扫码成功，保存当前位置对应的四轮脉冲，再以四轮绝对脉冲目标返回原扫码停车点；
- 如果走满 500 mm 仍未扫码成功，会停在前探极限持续等待；
- 只有成功扫码并返回原点后才进入后续路线。

优点：

- 不会把“固定反走 500 mm”当作回程，而是按实际已经走过的脉冲返回；
- 到扫码点前已经识别成功时不会多走；
- 无效码不会放行。

缺点：

- 二维码板的随机位置只通过一条直线最多前探 500 mm 搜索，不能横向搜索；
- 扫码成功仍是脉冲回位，不是坐标回位；
- 如果二维码始终识别不到，程序可能永久等待；
- 当前没有全局 3 分钟看门狗主动终止这种等待。

## 7. IMU 航向闭环逻辑

### 7.1 接收和校验

JY901/HWT101 的一帧是 11 字节。程序只接受：

- 帧头为 `0x55`；
- 类型为 `0x53` 的角度帧；
- 校验和正确。

Yaw 由帧中两个字节按小端 `int16_t` 解码，再换算成角度。

### 7.2 跨 ±180° 连续展开

传感器原始角度通常在 -180° 到 +180° 之间跳变。例如：

```text
179° → -179°
```

真实只转了 2°，不能误认为转了 -358°。程序对相邻帧差值进行包角处理，再累计成可超过一圈的连续航向。

这是一个正确且必要的实现。

### 7.3 每段运动结束后怎么锁航向

底盘平移或转向后，程序依次判断：

1. 四个电机目标脉冲是否全部到达；
2. 到达后等待 120 ms，让 IMU 数据和机械振动稳定；
3. 计算目标航向与当前航向的误差；
4. 如果误差超出对应容差，就低速原地补转；
5. 再次检查；
6. 误差连续稳定一定时间后，才认为本段结束。

容差随场景变化：

| 场景 | 航向容差 | 需要连续稳定 |
|---|---:|---:|
| 普通平移 | 0.40° | 200 ms |
| 工位精靠/视觉修正 | 0.20° | 400 ms |
| 转向 | 0.15° | 500 ms |
| 最终低速阶段 | 0.15° | 600 ms |

单次航向修正最多 12°。

### 7.4 长距离分段

一条平移命令超过 1100 mm 时，会自动拆成多个子段。每个子段完成后都重新锁一次航向。

例如第一批原料区到粗加工区的 1740 mm，会拆成：

```text
1100 mm + 640 mm
```

这样可以抑制长距离行驶中的角度漂移，但不能修复 X/Y 位置漂移。

## 8. 完整行驶路线：车辆到底怎么走

### 8.1 固定路线的几何前提

程序固定假设：

- 从启停区 1 出发；
- 起点车体中心约为 `(2215,2250)`；
- 初始实际车头 3、4 侧朝南；
- 机械臂 2、4 侧朝东；
- 工位作业时都让机械臂侧面对工位；
- 原料、粗加工、暂存的横向中线按 1200 mm 处理；
- 当前代码把圆环中心距场地边界设成 40 mm；
- 机械臂中心相对车体中心沿 2、4 侧偏移 225 mm。

### 8.2 理想几何点与实际代码累计点并不相同

代码中的几何注释理想点是：

| 位置 | 理想车心坐标 |
|---|---:|
| 启停区 1 | `(2215,2250)` |
| 二维码停车点 | `(2215,1200)` |
| 原料区 | `(1200,2135)` |
| 粗加工区 | `(1200,265)` |
| 暂存区 | `(265,1200)` |

但路线数组保留了多处实车补偿：`+20`、`+40`、`-20`、`-40`、`-50`、最终 `+50/+40`。因此按命令值累计得到：

| 动作点 | 开环推算车心坐标 | 说明 |
|---|---:|---|
| 起点 | `(2215,2250)` | 固定启停区 1 |
| 二维码停车点 | `(2215,1200)` | 未计前探；前探后会按脉冲回位 |
| 第一批原料 | `(1200,2135)` | 与当前代码理想点一致 |
| 第一批粗加工 | `(1200,245)` | 比理想点更靠南 20 mm |
| 第一批暂存 | `(265,1130)` | 比理想点更靠南 70 mm |
| 第二批原料 | `(1200,2105)` | 比第一批更靠南 30 mm |
| 第二批粗加工 | `(1200,215)` | 比理想点更靠南 50 mm |
| 第二批暂存 | `(265,1110)` | 比理想点更靠南 90 mm |
| 回程“Enter Start1”后 | `(2215,2160)` | 尚未完全到设计中心 |
| 最后 50/40 mm 后 | `(2255,2210)` | 程序最终推算位置 |

这些坐标不是传感器反馈，只是按代码命令值计算。

### 8.3 42 条路线命令的完整阶段说明

#### 阶段 A：启停区 1 → 二维码

1. 向 3、4 侧，也就是初始实际车头方向向南走 1050 mm；
2. 到 `(2215,1200)` 附近；
3. 扫码；必要时低速前探最多 500 mm；
4. 扫码成功后回到保存的扫码停车脉冲位置。

#### 阶段 B：二维码 → 第一批原料区

1. 向 1、3 侧横移 1015 mm，到场地 X=1200 中线附近；
2. 向 1、2 侧移动 785 mm，到原料区前 150 mm；
3. 逆时针转 90°，使机械臂 2、4 侧朝北；
4. 向 2、4 侧低速精靠 150 mm；
5. 到 `(1200,2135)` 附近执行第一批原料动作。

#### 阶段 C：第一批原料区 → 第一批粗加工区

1. 向 1、3 侧长距离移动 `1870-150+20=1740 mm`；
2. 该长段自动拆成 1100 mm + 640 mm，每段结束做 IMU 航向修正；
3. 逆时针转 180°，使机械臂侧朝南；
4. 向 2、4 侧低速精靠 150 mm；
5. 到开环推算 `(1200,245)` 执行第一批粗加工动作。

#### 阶段 D：第一批粗加工区 → 第一批暂存区

1. 向 1、3 侧移动 `935-50=885 mm` 回到场地中部附近；
2. 向 3、4 侧移动 `935-150=785 mm` 到暂存区前；
3. 顺时针转 90°，使机械臂侧朝西；
4. 向 2、4 侧低速精靠 150 mm；
5. 到开环推算 `(265,1130)` 执行第一批暂存动作。

#### 阶段 E：第一批暂存区 → 第二批原料区

1. 保持机械臂侧朝西，向 1、3 侧移动 935 mm，回到 X=1200 附近；
2. 向 3、4 侧移动 `935-150=785 mm` 到原料区前；
3. 顺时针转 90°，使机械臂侧朝北；
4. 向 2、4 侧低速进入 `150+40=190 mm`；
5. 到开环推算 `(1200,2105)` 执行第二批原料动作。

#### 阶段 F：第二批原料区 → 第二批粗加工区

1. 向 1、3 侧移动 `1870-150+40=1760 mm`；
2. 自动拆成 1100 mm + 660 mm；
3. 逆时针转 180°，使机械臂侧朝南；
4. 向 2、4 侧低速进入 `150-20=130 mm`；
5. 到开环推算 `(1200,215)` 执行第二批粗加工动作。

#### 阶段 G：第二批粗加工区 → 第二批暂存区

1. 向 1、3 侧移动 `935-40=895 mm`；
2. 向 3、4 侧移动 785 mm 到暂存区前；
3. 顺时针转 90°，使机械臂侧朝西；
4. 向 2、4 侧低速精靠 150 mm；
5. 到开环推算 `(265,1110)` 执行第二批同色码垛。

#### 阶段 H：第二批暂存区 → 启停区 1

1. 向 1、3 侧移动 935 mm，回到场地 X=1200 附近；
2. 再向 1、3 侧移动 950 mm，到右侧回程通道 X≈2150；
3. 向 3、4 侧移动 950 mm，到上方转弯/回程区域 Y≈2150；
4. 切换最终低速模式；
5. 向 3、4 侧移动 100 mm；
6. 向 1、3 侧移动 65 mm，代码把此步称为进入 Start1；
7. 执行 `FINAL_ALIGN`；
8. 保持 3000 ms；
9. 再向 3、4 侧移动 50 mm；
10. 再向 1、3 侧移动 40 mm；
11. M5 回到旧坐标 -90°；
12. 程序结束并关闭驱动。

### 8.4 最终停车的严重风险

`FINAL_ALIGN` 目前没有调用红外、视觉或其他定位传感器。代码进入这个命令后只是：

```text
HMI显示 ALIGN
finalAlignmentFinished = true
```

也就是说，它只是一个名称为“最终对齐”的同步点，并没有真实对齐。

按最后的累计坐标 `(2255,2210)`，若车体外廓在当前朝向仍为 X方向 230 mm、Y方向 300 mm，则：

```text
X范围约为 2140～2370
Y范围约为 2060～2360
```

而启停区 1 的范围是：

```text
X = 2100～2400
Y = 2100～2400
```

所以车体 Y 最小值约为 2060 mm，可能仍有约 40 mm 在启停区外。这里只计算了代码给出的名义底盘外廓，还没有加入机械臂、夹爪或其他突出结构。

这是必须通过实车尺寸、规则对“完全进入”的判定和终点传感器共同验证的高风险项。

## 9. MaixCAM 通信：能够确认的部分

### 9.1 当前仓库缺少正式视觉端源码

主程序注释多次提到 `vision-2.py`，但在当前项目和已检查的 `D:\SRTP` 中都没有找到该文件。

因此本说明只能确认：

- STM32 发什么请求；
- STM32 期待什么响应；
- STM32 收到坐标后如何计算；
- STM32 如何做稳定性判断和动作闭环。

不能确认的内容包括：

- MaixCAM 实际使用 LAB、HSV、YOLO、霍夫圆还是轮廓；
- 黄色是否已正确加入；
- 多目标时相机端究竟如何选择目标；
- 圆检测是否真的只选择最近圆；
- 光照自适应、曝光、白平衡、ROI、形态学参数；
- 丢失目标时相机端是否发送特殊值；
- 相机端运行分辨率是否确实为 320×240；
- 相机端程序是否与当前 STM32 协议完全一致。

在正式视觉程序补回仓库之前，不能把整个视觉链路称为已核验。

### 9.2 STM32 发给 MaixCAM 的请求

请求帧固定为 3 字节：

```text
AA  模式  BB
```

模式含义：

| 模式 | STM32 认为的含义 |
|---:|---|
| `0x00` | 停止识别 |
| `0x01` | 找颜色 1，红色 |
| `0x02` | 找颜色 2，黄色 |
| `0x03` | 找颜色 3，蓝色 |
| `0x04` | 找颜色 4，绿色 |
| `0x07` | 找圆 |

切换识别模式时：

1. 先发送停止模式；
2. 清空串口缓存；
3. 等待 100 ms；
4. 发送新模式；
5. 之后每 1000 ms 重发一次请求。

### 9.3 MaixCAM 返回格式

STM32 期待一行 ASCII：

```text
x,y\n
```

例如：

```text
163,118
```

坐标必须满足：

```text
0 ≤ x ≤ 319
0 ≤ y ≤ 239
```

超过范围、格式错误或不是完整一行都会被丢弃。

每个有效坐标都有：

- 坐标值；
- 单调增加的序号；
- 接收时间。

工位状态机只消费“比上一次更新的新坐标”，并拒绝超过 1500 ms 的旧坐标。

## 10. 原料区视觉逻辑

### 10.1 原料区视觉控制谁

原料区只根据视觉移动机械臂，不移动底盘。

也就是说：

- 车停到固定原料区动作点；
- 请求当前任务要求的颜色；
- 找到稳定目标；
- 计算 M5 旋转和 M6 伸缩；
- M7 下探抓取；
- 把物料送到车载物料盘。

优点是不会为了追随转盘上的物料让整车在工位前来回晃动。缺点是可抓范围完全受机械臂工作空间限制，停车误差过大时无法用底盘补偿。

### 10.2 目标稳定判断

当前任务物料颜色来自：

```text
taskColors[当前批次][当前物料序号]
```

程序收到坐标后建立稳定窗口，要求：

- 至少 3 个样本；
- 从第一个样本开始持续至少 1000 ms；
- 所有样本的 X 最大值与最小值之差不超过 5 px；
- 所有样本的 Y 最大值与最小值之差不超过 5 px；
- 相邻样本间隔不能超过 1200 ms。

任何一项不满足，稳定窗口就从最新点重新开始。

稳定后对窗口内所有坐标取平均，只计算一次抓取姿态。

这个逻辑的目的，是等待旋转原料盘停止后再抓，避免追抓运动中的物料。

### 10.3 像素到毫米的两档映射

假设画面大小为 320×240，中心是：

```text
(160,120)
```

先计算：

```text
dx = x - 160
dy = y - 120
r = sqrt(dx² + dy²)
```

根据目标离画面中心的像素半径选择比例：

```text
r ≤ 50 px：70/72 mm/px ≈ 0.9722 mm/px
r > 50 px：40/72 mm/px ≈ 0.5556 mm/px
```

横纵坐标使用同一档比例，避免一个轴用近档、另一个轴用远档而改变目标向量方向。

### 10.4 机械臂姿态计算

已知机械臂旋转轴到相机中心的标定距离为 135 mm。

程序把：

- 图像 x 偏差转换成 M5 切向偏差；
- 图像 y 偏差转换成机械臂径向伸缩偏差；
- 图像 y 向下与机械臂向外的方向设为相反。

近似计算过程是：

```text
切向距离 = dx × mmPerPixel
径向距离 = 135 + dy × mmPerPixel × (-1)
目标半径 = sqrt(径向距离² + 切向距离²)
M6伸长量 = 目标半径 - 135
M5新坐标角 = -atan2(切向距离, 径向距离)
M7目标高度 = -73 mm
```

如果计算出的 M6 伸长量小于 0 mm 或大于 150 mm，程序直接进入故障，不会勉强执行。

### 10.5 原料区每个物料的动作

对每个物料：

1. 请求当前颜色；
2. 等待坐标稳定；
3. 计算原料目标姿态；
4. 打开夹爪；
5. M7 升到最高；
6. M6 完全缩回；
7. M5 转到目标角；
8. M6 伸到目标长度；
9. M7 下探到 -73 mm；
10. 夹爪闭合；
11. M7 升起；
12. M6 缩回；
13. M5 转向车载物料盘位置；
14. M6 伸到目标位置；
15. M7 下降到载物盘放置高度；
16. 夹爪打开；
17. M7 升起；
18. M6 缩回；
19. M5 回标准工位角；
20. 完成一次抓取计数；
21. 载物盘转到下一个槽位；
22. 开始识别下一件。

三件完成后，原料区动作结束。

## 11. 粗加工区与暂存区圆视觉逻辑

### 11.1 圆视觉控制谁

与原料区不同，粗加工区和暂存区的圆视觉用于移动底盘，不直接根据视觉计算每个圆环的机械臂姿态。

逻辑是：

1. 请求模式 7 找圆；
2. 把检测到的圆移动到画面中心；
3. 认为这个圆是 2 号中间圆；
4. 再根据固定几何关系计算 1、2、3 号圆的机械臂姿态。

### 11.2 圆心到画面中心的闭环

收到圆心 `(x,y)` 后：

```text
dx = x - 160
dy = y - 120
r = sqrt(dx² + dy²)
```

圆视觉比例为：

```text
r ≤ 50 px：70/36 mm/px ≈ 1.9444 mm/px
r > 50 px：40/36 mm/px ≈ 1.1111 mm/px
```

然后根据相机安装符号映射为车体 forward/left 修正量。

单次修正向量如果超过 150 mm，会按比例缩短到 150 mm，防止一次识别异常让车突然大幅移动。

每次修正后：

1. 停止当前识别请求；
2. 低速移动底盘；
3. 等底盘脉冲到位；
4. 用 IMU 把车体航向重新锁回目标角；
5. 再次请求圆坐标；
6. 重复直到圆心误差不超过 5 mm。

### 11.3 居中稳定条件

进入 5 mm 容差后还不能立刻通过，还要求：

- 至少 2 个居中样本；
- 居中状态持续至少 500 ms；
- 相邻样本间隔不超过 1200 ms。

通过后才开始机械臂放料。

### 11.4 暂存区为什么先走 -30 mm

当前 STM32 协议只收到一个圆心 `(x,y)`，没有圆环编号。主程序注释假定 MaixCAM 返回“离画面中心最近的圆”。

为了让暂存区的 2 号中间圆成为最近圆，程序在暂存区开始视觉定位前先做：

```text
车体 forward = -30 mm
```

这 30 mm 被记录到“视觉修正累计脉冲”里。离开工位前会与其他视觉修正一起反向走回。

这个做法是一种工程补丁，而不是可靠的圆环身份识别。它依赖：

- 原路线停车误差处于预期范围；
- 三个圆都能被识别；
- 相机端确实选最近圆；
- 30 mm 足以让中间圆成为最近圆；
- 没有误选旁边圆或其他圆形物体。

任何前提不成立，都可能把 1 号或 3 号圆错误当作 2 号圆，随后三个放置位置整体错位。

### 11.5 1、2、3 号环机械臂几何

通过视觉把“中间圆”居中后，程序认为：

- 1 号圆在画面中心左侧 150 mm；
- 2 号圆就在画面中心；
- 3 号圆在画面中心右侧 150 mm。

机械臂旋转轴到相机中心距离为 135 mm。

对于 1 或 3 号环：

```text
目标半径 = sqrt(135² + 150²) ≈ 201.8 mm
M6伸长量 ≈ 201.8 - 135 = 66.8 mm
M5角度大小 ≈ atan2(150,135) = 48.0°
```

所以大致是：

| 圆环 | M5 新坐标角 | M6 伸长 |
|---|---:|---:|
| 1号 | +48° 左右 | 66.8 mm 左右 |
| 2号 | 0° | 0 mm |
| 3号 | -48° 左右 | 66.8 mm 左右 |

高度由当前动作决定。

### 11.6 粗加工区动作

每一批在粗加工区都执行两个阶段。

第一阶段：从载物盘向三个目标圆环放置

1. 视觉把中间圆对准画面中心；
2. 按当前批次任务码的 `taskPositions` 依次选择 1、2、3 号环；
3. 从载物盘对应槽位抓起；
4. 放到粗加工目标圆环；
5. 放置下降量为 150 mm；
6. 每完成一次，放置计数加 1；
7. 载物盘转到下一槽位。

第二阶段：从三个圆环按原顺序抓回载物盘

1. 物料序号重新从 0 开始；
2. 从任务码指定圆环抓起；
3. 放回载物盘；
4. 每完成一次，抓取计数加 1；
5. 三个都抓回后，恢复全部视觉底盘修正。

### 11.7 暂存区动作

第一批：

- 按第一批位置组，把三个物料分别放到 1、2、3 号环；
- 放置下降量为 150 mm；
- 形成码垛底层。

第二批：

- 不能简单使用第二批位置组作为最终暂存位置；
- 程序先取第二批当前物料的颜色；
- 在第一批颜色列表里找到相同颜色；
- 使用该第一批物料对应的暂存位置；
- 放到第一批同色物料上；
- 第二层放置下降量为 90 mm。

例如：

```text
第一批颜色：1 3 4
第一批位置：2 1 3

第二批当前颜色：4
```

程序会在第一批找到颜色 4 位于第 3 个物料，于是使用第一批第 3 个物料的位置 3，把第二批颜色 4 放到位置 3 的第一批颜色 4 上。

这个“按颜色查第一批底层位置”的逻辑是正确的同色码垛思路。

### 11.8 为什么离站前要反向恢复视觉修正

粗加工区或暂存区为了圆心居中，底盘可能移动了若干次。程序把每次移动换算成四轮脉冲并累加。

完成全部机械臂动作后，程序发送：

```text
累计脉冲的相反数
```

让底盘尽量回到进入视觉闭环前的开环路线基准位置，然后再用 IMU 重新锁航向。

优点：

- 不会让工位视觉修正永久污染后续固定路线；
- 多次修正也能统一恢复；
- 恢复后还会重新校正航向。

限制：

- 仍然是脉冲反走，不是世界坐标回位；
- 如果修正过程中发生打滑，反向同样脉冲不一定回到原位置；
- 机械臂动作产生的平移误差没有被测量；
- 原料区完全不做这种底盘回位。

## 12. 机械臂状态机

### 12.1 M5、M6、M7 的含义

- M5：机械臂底座旋转；
- M6：机械臂径向伸缩；
- M7：机械臂上下升降。

M6 最大软件伸长为 150 mm。  
M7 软件高度范围为 0 到 -160 mm，0 表示最高，负数表示下降。

### 12.2 新旧 M5 角度坐标

程序保留了旧代码的 M5 角度定义，同时为工位动作包装了一层新坐标：

```text
旧坐标 -90° 的物理姿态 = 工位新坐标 0°
```

工位动作中：

- 新坐标正角：逆时针；
- 新坐标负角：顺时针；
- 车载物料盘方向大约是新坐标 -100°。

调试时如果把日志里的旧坐标和工位公式里的新坐标混在一起，很容易误判机械臂转向。

### 12.3 标准化动作

每次进入原料、粗加工或暂存动作前，先执行机械臂标准化：

```text
打开夹爪
  → M7升到最高
  → M6完全缩回
  → M5转到工位新坐标0°
  → 等待M5稳定
```

同时载物盘转到第一个工作槽位。

### 12.4 通用“源位置 → 目标位置”搬运序列

所有抓取/放置复用同一套非阻塞搬运状态机：

1. 打开夹爪；
2. M7 升到最高；
3. M6 缩回；
4. M5 转到源位置角度；
5. 等 M5 停稳；
6. M6 伸到源位置；
7. M7 降到源高度；
8. 夹爪闭合；
9. M7 升到最高；
10. M6 缩回；
11. M5 转到目标位置角度；
12. 等 M5 停稳；
13. M6 伸到目标位置；
14. M7 降到目标高度；
15. 夹爪打开；
16. M7 升到最高；
17. M6 缩回；
18. M5 回工位新坐标 0°；
19. 等待 M5 稳定；
20. 搬运完成。

优点是每一步都有明确阶段，`loop()` 仍能继续接收串口和处理急停。

### 12.5 M6/M7 通信与保护

M6/M7 使用 EMM V5 类串口步进协议，程序会：

- 发送使能帧；
- 发送相对位置运动帧；
- 接收位置命令 ACK；
- 每 30 ms 查询状态；
- 检查驱动是否使能；
- 检查堵转/保护状态位；
- 接收可能存在的主动到位帧；
- 根据移动距离估算动作超时，限制在 5～30 秒；
- 超过软件行程范围直接拒绝；
- 出错时停止轴并让整场路线进入故障。

这部分比“只发完命令然后固定 delay”可靠得多。

但位置依然是软件累计。驱动返回“运动完成”不等于系统完成了物理绝对寻零。

### 12.6 夹爪和载物盘

夹爪标定：

| 状态 | 角度 |
|---|---:|
| 闭合 | 99° |
| 常规打开 | 7° |
| 最大打开 | -90° |

载物盘有三个工作槽位，每次物料搬运完成后旋转到下一槽位。程序按动作完成定时等待舵机稳定，不读取舵机实际到位位置作为闭环。

## 13. HMI 显示逻辑

### 13.1 任务码

完整 15 字符任务码被拆成两行显示：

```text
t3：前8字符，例如 134+123+
t8：后7字符，例如 314+231
```

两行合起来是完整任务码。

### 13.2 计数

- `n5`：程序认为完成的抓取数；
- `n6`：程序认为完成的放置数。

若整套两批流程全部完成，按当前状态机应累计：

```text
抓取：12
  原料区抓上车 6 次
  粗加工区重新抓回车 6 次

放置：12
  粗加工区放置 6 次
  暂存区放置 6 次
```

再次强调：这是动作完成计数，不是物料成功检测。

### 13.3 状态文字

HMI 会出现的典型状态包括：

- `READY`：上电准备完成；
- `IMUWAIT`：等待有效 IMU；
- `RUN`：路线运行；
- `SCAN`：二维码扫描；
- `SCANMAX`：前探已到 500 mm 极限；
- `QRBACK`：扫码后返回原停车点；
- `RAW1` / `RAW2`：第一批/第二批原料；
- `PROCESS1` / `PROCESS2`：粗加工；
- `STORAGE1` / `STORAGE2`：暂存；
- `SLOW`：最终低速；
- `ALIGN`：进入名义最终对齐点，但当前无真实对齐；
- `HOLD`：终点保持；
- `ARM0`：M5 回标准姿态；
- `FINISH`：完成；
- `FAULT`：程序故障；
- `STOP`：人工长按停止。

### 13.4 航向和电池

- `x0` 每 100 ms 更新一次当前连续航向角 ×100；
- `x1` 每 500 ms 显示滤波后的电池电压 ×100；
- 电池 ADC 使用 10 kΩ + 1 kΩ 分压假设，标定系数当前为 1.0，必须用万用表实测校准。

## 14. 故障与安全逻辑

### 14.1 会触发整场故障的典型条件

- IMU 数据超过 600 ms 未更新；
- M6/M7 命令错误；
- M6/M7 未使能；
- M6/M7 堵转或保护；
- M6/M7 动作超时；
- 机械臂目标超出软件行程；
- MaixCAM 请求模式非法；
- 任务码未正确解码却进入工位；
- 夹爪或载物盘舵机离线；
- 第二批颜色无法在第一批中找到对应码垛位置；
- 圆环编号参数非法；
- 人工长按停止。

### 14.2 故障后统一动作

`routeFault()` 会：

1. 取消扫码动作；
2. 取消载物盘延迟动作；
3. 使 M6/M7 软件参考失效；
4. 停止并关闭底盘；
5. 停止并关闭 M5；
6. 急停 M6/M7；
7. 停止 MaixCAM 请求；
8. 进入 `PROGRAM_FAULT`；
9. HMI 显示 `FAULT`；
10. 调试串口打印故障原因。

### 14.3 当前没有启用的底盘运动超时

代码虽然定义了：

- 普通运动 20 秒超时；
- 转向 16 秒超时；

但：

```text
ENABLE_MOTION_TIMEOUTS = false
```

所以底盘脉冲未完成或航向一直无法稳定时，这两个超时当前不会触发。

视觉等待同样没有完整的工位总超时。如果相机一直不回坐标，程序可能一直停留在当前工位。

### 14.4 缺失的比赛级看门狗

当前没有实现：

- 全场 3 分钟总计时；
- 预计剩余动作时间判断；
- 长时间无状态推进的监控；
- 15 秒静止风险监控；
- 超时后安全收臂或返回策略。

## 15. 当前版本的优点

### 15.1 软件结构优点

1. **主循环总体非阻塞**  
   电机、IMU、二维码、视觉、机械臂、HMI 和急停可以持续被服务。

2. **总路线表直观**  
   42 条命令按比赛流程顺序排列，路线意图容易核对。

3. **长距离分段并逐段锁航向**  
   比一次性盲走近 2 m 更稳。

4. **IMU 跨 ±180° 展开正确**  
   避免 179° 与 -179° 的角度跳变错误。

5. **二维码校验严格**  
   长度、分隔符、颜色范围、重复颜色、两批颜色集合和位置排列均校验。

6. **视觉数据有新旧帧管理**  
   有序号、接收时间和 1.5 秒过期判断，不会轻易拿旧坐标执行新动作。

7. **原料目标有稳定窗口**  
   能避免转盘还在转时立即抓取。

8. **圆心修正有单次 150 mm 限幅**  
   降低异常坐标造成大幅误动作的风险。

9. **工位视觉修正可反向恢复**  
   尽量保持固定路线的基准。

10. **M6/M7 有实际通信状态检查**  
    包含 ACK、状态查询、堵转/保护、超时和行程保护。

11. **机械臂动作复用统一状态机**  
    三类工位不需要各写一套易出错的阻塞动作。

12. **第二批同色码垛映射思路正确**  
    通过颜色查找第一批底层位置，不是错误照搬第二批粗加工位置。

13. **故障处理相对统一**  
    多类错误都能走同一停机路径。

14. **显示内容覆盖规则重点**  
    有完整任务码、抓取数和放置数。

15. **当前固件能够正常编译**  
    已执行 PlatformIO 编译并成功：
    - Flash 约 68096 / 131072，约 52%；
    - RAM 约 7012 / 524288，约 1.3%。

## 16. 当前版本的缺点和比赛风险

以下不是语法或编译问题，而是“代码即使正常运行，也可能在真实赛场失分或失败”的系统风险。

### 16.1 P0：赛前必须解决或明确接受的风险

#### 1. 只支持启停区 1

规则允许抽到启停区 2，当前路线、初始姿态、二维码路线和回程只实现启停区 1。抽到启停区 2 时不能直接运行。

#### 2. 没有障碍物检测和避障

规则允许黑色障碍物随机放置。当前是固定路线数组，没有：

- 前向测距；
- 黑色障碍物视觉检测；
- 局部绕行；
- 动态路径重规划；
- 绕行后回归路线。

固定路线与障碍物冲突时，可能直接碰撞或卡死。

#### 3. 没有 X/Y 位置闭环

IMU 只能保证朝向，不能保证实际坐标。两批路线距离长、横移多、转向多，误差会积累。

#### 4. 正式 MaixCAM 程序缺失

没有视觉端正式源码，就无法进行版本控制、协议联调、黄色识别确认和现场光照调参。

#### 5. 圆视觉没有 1/2/3 号身份

仅靠“最近圆”和暂存区 -30 mm 偏置选中间圆，存在整个位置映射错一格的风险。

#### 6. 最终停车可能没有完全进入启停区

按名义外廓推算，最终 Y 方向可能仍有约 40 mm 在区外，而且没有真正终点对齐。

#### 7. 原料区与二维码随机性覆盖不足

原料区 X 位置和二维码板位置按规则可能改变。当前：

- 原料区固定到 X=1200；
- 二维码只沿直线前探；
- 没有扫描规定随机区域的能力。

#### 8. 运动和视觉可能无限等待

底盘超时开关关闭，视觉无完整工位超时，也没有全场 3 分钟看门狗。

### 16.2 P1：可靠性风险

#### 1. M5/M6/M7 没有物理寻零

上电姿态完全依赖人工摆放，任何一次摆错都会让机械臂坐标整体错误。

#### 2. 计数不等于成功

没有：

- 夹爪物料检测；
- 夹爪电流/力反馈；
- 抓后视觉确认；
- 放后视觉确认；
- 载物盘物料存在检测。

所以掉料、空抓、夹偏时计数仍可能增加。

#### 3. 40 mm 圆环边界偏移与规则几何不一致

规则中的粗加工区、暂存区台面深度约 150 mm，名义中线距边界应约为 75 mm。当前代码继续采用 40 mm，相差约 35 mm。

按机械臂中心偏移 225 mm 反算：

- 若圆心距边界 40 mm，原料/粗加工/暂存车心为 2135/265/265；
- 若圆心距边界 75 mm，理想车心更接近旧仿真中的 2100/300/300。

这必须以 2026 省赛正式尺寸图和实物平台测量为准重新确认，不能只凭旧实调数字。

#### 4. 两档毫米/像素映射不连续

原料比例在 50 px 临界点会从约 0.9722 突然变成约 0.5556；圆比例会从约 1.9444 突然变成约 1.1111。目标在临界点附近抖动时，估算距离可能突变。

更合理的方法是用相机标定曲线、机械臂高度和透视模型连续计算。

#### 5. HMI 正确统计缺少真实性

规则要求的是正确抓取/放置统计。当前只能显示已执行动作数，出现空抓时会与事实不符。

#### 6. 舵机只检查上线，不检查每次实际到位

载物盘和夹爪动作主要依赖固定等待时间。

### 16.3 P2：维护与调试风险

#### 1. 单个 `main.cpp` 太大

二维码、IMU、底盘、机械臂、视觉、路线、HMI 和故障全部集中在一个文件，后期多人协作和单元测试困难。

#### 2. 参数与逻辑混在一起

场地几何、相机标定、机械臂行程、路线补偿、速度和比赛模式都在同一文件中。现场调参容易误改逻辑。

#### 3. 路线仿真和预检脚本已落后

`test/route_preflight.py` 当前仍检查旧常量和旧的“绕过二维码”路线，所以测试失败。该失败不是固件编译失败，而是测试脚本与当前主程序失配。

`route-simulator` 的部分标注也仍是旧路线，只能理解大致形状，不能作为当前程序的精确验证。

#### 4. 缺少统一日志事件编号

当前调试日志很多，但尚未形成可自动分析的比赛时间线，例如每个状态的进入、退出、耗时、视觉重试数和错误码。

## 17. 建议的实车阅读和调试顺序

不要一上来直接跑完整 3 分钟流程。建议按下面顺序验证。

### 第一步：确认机械零位和正方向

1. 断开底盘或架空；
2. 人工把 M5、M6、M7 放到程序规定的上电零位；
3. 单独验证 M5 新旧坐标；
4. 单独验证 M6 0～150 mm；
5. 单独验证 M7 0～-160 mm；
6. 确认夹爪 99°/7°/-90°；
7. 确认载物盘三个槽位。

### 第二步：确认四个车体方向

分别只走很短距离，确认：

- SIDE_12；
- SIDE_34；
- SIDE_13；
- SIDE_24；
- 顺时针；
- 逆时针。

必须在车体转过 90° 后再重复确认一次，防止把车体方向与世界方向混淆。

### 第三步：标定纵移、横移和旋转

- 纵向至少测 0.5 m、1 m、2 m；
- 横向至少测 0.5 m、1 m；
- 顺、逆时针分别测 90°、180°；
- 在比赛地面、比赛载荷、电池不同电量下重复；
- 不应只用悬空轮或光滑室内地面参数。

### 第四步：补回并冻结 MaixCAM 正式程序

至少确认：

- 模式 1～4 对应 2026 四种颜色；
- 模式 7 的返回选择规则；
- 分辨率是 320×240；
- 返回格式严格为 `x,y\n`；
- 无目标时的行为；
- 多目标时的行为；
- 相机曝光、白平衡、增益；
- 黄色与绿色的区分；
- 相机程序版本号。

### 第五步：分别跑三个工位

1. 原料区三色稳定识别和抓取；
2. 粗加工区 1、2、3 号位置；
3. 暂存区第一层；
4. 暂存区第二层同色码垛；
5. 验证视觉修正后反向回位。

### 第六步：只跑路线并测量实际坐标

即使存在 `PATH_ONLY_TEST`，也要清楚它只模拟工位时间和计数，不能验证真实物流动作。

每个工位测：

- 车心实际 X/Y；
- 车体实际航向；
- 与目标圆环的相机误差；
- 视觉修正总量；
- 反向恢复后的偏差。

### 第七步：完整计时

记录：

- 扫码耗时；
- 六次原料识别耗时；
- 24 次通用搬运动作耗时；
- 六个工位视觉定位耗时；
- 全路线耗时；
- 最坏一次耗时；
- 视觉失败重试后的耗时。

目标不是“平均刚好小于 3 分钟”，而是最坏情况仍有安全余量。

### 第八步：按规则做随机测试

- 启停区 1 / 2；
- 二维码板不同位置；
- 原料区不同位置；
- 障碍物不同位置；
- 不同任务码；
- 不同颜色顺序；
- 不同圆环位置排列；
- 不同光照；
- 电池满电与低电；
- 人工轻推或轮子轻微打滑；
- 中途暂时丢失视觉。

## 18. 本 version1 文档的最终判断

当前程序的“流程理解”可以概括为：

```text
PB9一次启动
  → IMU建立本场0°
  → 固定路线到二维码
  → 严格解析两批颜色和位置
  → 第一批：视觉抓原料 → 圆心修车 → 粗加工放/抓 → 暂存放底层
  → 第二批：视觉抓原料 → 圆心修车 → 粗加工放/抓 → 按第一批颜色位置码垛
  → 固定路线返回启停区1
  → 名义FINAL_ALIGN但无真实传感器动作
  → 最后两段实调位移
  → 收M5、停机、显示结果
```

从软件工程角度，它已经具有一套不错的非阻塞状态机框架；从 2026 省赛的真实随机场景角度，它仍缺少几项决定成败的闭环能力。

最先应该解决的不是继续微调某个固定距离，而是：

1. 找回并验证正式 MaixCAM 程序；
2. 明确支持启停区 1 和启停区 2；
3. 给圆检测增加明确的环号或三圆整体几何识别；
4. 实现最终启停区真实对齐；
5. 增加障碍物感知与绕行；
