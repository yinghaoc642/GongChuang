# 2026 浙江省赛搬运机器人从零设计完整方案

> 方案性质：不继承当前 `src/main.cpp` 的路线、状态机和工位实现，从零设计  
> 已知能力基线：仅把 `true_example/Move_perfect.cpp` 作为“底盘已经能平移、横移、转向并使用 IMU 修正航向”的能力证明  
> 规则基线：2026 浙江省赛命题文件与 2026 搬运初赛评分表

## 0. 方案结论

如果完全没有现在这份 `main.cpp`，只知道你已经通过 `Move_perfect.cpp` 实现了麦轮底盘的基本移动和转动，我建议从零搭建下面这套系统：

```text
STM32H750 实时主控
  + 现有 STEP/DIR 麦轮底盘
  + JY901/HWT101 航向
  + OPS9 或等效 X/Y 位置传感器
  + 低位二维激光雷达，或“多路测距 + 前视视觉”组合
  + MaixCAM 工位视觉
  + 独立二维码扫描模块
  + M5/M6/M7 机械臂、夹爪、三槽载物盘
  + M5/M6/M7 物理限位寻零
  + 夹爪/载物盘物料存在检测
  + HMI 显示与现场标定
```

软件不采用“一长串固定距离命令”，而采用：

```text
2026比赛任务状态机
  → 场地可通行区域地图
  → 启停区1/2参数化
  → 世界坐标路径规划
  → 障碍物在线更新与重新规划
  → X/Y/航向闭环走点
  → 工位视觉二次精定位
  → 机械臂非阻塞搬运
  → 抓取/放置成功确认
  → 剩余时间与安全监督
```

这套方案的核心思想是：

> 底盘导航负责“把车可靠送到工位附近”，工位视觉负责“把机械臂或车对到毫米级目标”，机械臂负责“完成并确认抓取和放置”，安全监督器负责“任何模块失效时不让机器人继续盲跑”。

### 0.1 本方案明确不继承的内容

以下内容即使在旧代码中存在，本方案也不默认采用：

- 固定启停区 1；
- 固定 42 条路线；
- 固定二维码停车点；
- 固定原料区中心；
- 固定 40 mm 圆环边界偏移；
- `+20/-40/+50` 一类经验路线补偿；
- 只靠步进脉冲累计推算世界坐标；
- 只返回一个最近圆的视觉协议；
- 没有动作的 `FINAL_ALIGN`；
- 没有障碍物检测的固定路线。

### 0.2 从 `Move_perfect.cpp` 只确认哪些能力

根据文件和你的中期考核进度，本方案把下面能力视为已经具备或至少已经做过：

## 1. 2026 省赛对方案的硬约束

### 1.1 场地和通行约束

- 场地尺寸：2400 mm × 2400 mm；
- 中央十字灰色车道宽度：400 mm；
- 四个淡黄色区域：450 mm × 450 mm；
- 机器人全部离开启停区后，只能在灰色车道上行驶；
- 进入其他颜色区域会结束比赛；
- 场地和装置存在实际摆放误差，机器人必须适应；
- 场地存在随机数量、随机位置的黑色模拟障碍物；
- 障碍物尺寸为 φ50 mm × 100 mm。

这意味着：

1. 不能只写一条不看环境的固定路线；
2. 路径规划必须把非灰色区域当作绝对禁区；
3. 障碍物必须在线加入地图；
4. 机器人外廓而不是车心必须保持在灰色区域；
5. 转向时要检查旋转包络，不能只检查转向前后的两个矩形。

### 1.2 区域和随机位置

- 启停区有两处，尺寸均为 300 mm × 300 mm；
- 出发位置现场抽签；
- 原料区位于上侧规定范围，横向位置可在约 1100～1300 mm 范围变化；
- 二维码板在右侧规定范围内随机摆放；
- 原料区、粗加工区、暂存区的实物位置允许存在偏差。

所以软件中必须把：

```text
StartZone1
StartZone2
QrBoardPose
RawStationPose
ProcessStationPose
StorageStationPose
```

定义为运行时配置或传感器观测，不能全部编译成唯一常量。

### 1.3 原料、圆环与物料

- 原料台面为直径 300 mm 的圆盘；
- 总高度约 80～100 mm；
- 三个物料位置按 120° 分布；
- 三个位置所在圆直径约 200 mm；
- 转盘每圈约 6～10 秒，随机停止；
- 暂存区、粗加工区为 580 mm × 150 mm；
- 三个圆环相邻中心距约 150 mm；
- 1 号与 3 号圆环中心间距约 300 mm；
- 圆环数字 1、2、3 面向赛场中心；
- 物料最大尺寸不超过 80 mm；
- 物料重量不超过 100 g；
- 决赛第一阶段颜色包括红、黄、蓝、绿；
- 每次任务选择三种不同颜色，每种颜色有两件，构成第一批和第二批。

### 1.4 任务码

任务码格式：

```text
颜色组1+位置组1+颜色组2+位置组2
```

例如：

```text
134+123+314+231
```

含义：

- 第一组：第一批三个物料的颜色和抓取顺序；
- 第二组：第一批三个物料在粗加工区和暂存区的位置；
- 第三组：第二批三个物料的颜色和抓取顺序；
- 第四组：第二批三个物料在粗加工区的位置；
- 第二批在暂存区的码垛位置不是直接使用第四组，而是由第一批同色物料的位置决定。

### 1.5 正式运行流程

```text
一键启动
  → 扫描二维码并显示任务码
  → 第一批原料区按颜色顺序抓3件到车载物料盘
  → 第一批粗加工区按位置放3件
  → 第一批粗加工区按规定顺序抓回3件
  → 第一批暂存区按位置放3件作为底层
  → 第二批原料区按颜色顺序抓3件
  → 第二批粗加工区按位置放3件
  → 第二批粗加工区按规定顺序抓回3件
  → 第二批暂存区放到第一批同色物料上
  → 返回抽签确定的启停区
  → 显示正确抓取数和正确放置数
```

整个过程中：

- 每次只能抓取 1 个物料；
- 必须把当前物料放到机器人上，或者当前抓取动作已经失败，才能抓下一个；
- 不允许夹爪一直夹着物料跨区域运输；
- 物料未放到机器人上时不能向下一个区域移动；
- 时间会连续计算。

### 1.6 时间与启动

- 每个参赛队有两次运行机会；
- 每轮调试时间 3 分钟；
- 每轮正式运行时间 3 分钟；
- 统一指令发出后 5 秒内必须一键启动；
- 每轮只有一次启动机会；
- 补充解析资料提示机器人长时间无移动可能被结束比赛，因此软件不应无限等待视觉或传感器。

设计目标不能是“平均恰好 180 秒完成”，而应是：

```text
典型完成时间 ≤ 150 秒
最坏可接受时间 ≤ 165 秒
至少保留 15 秒用于避障、视觉重试和回启停区
```

### 1.7 放置精度为什么是系统核心

评分圆环的第 1 环外径仅比物料最大直径大约 3 mm。

理想几何下，如果希望物料不遮住第 1 环外圈，径向中心误差余量只有约：

```text
3 mm / 2 = 1.5 mm
```

还没有扣除：

- 3D 打印尺寸误差；
- 圆环印刷误差；
- 夹爪中心偏差；
- 相机标定误差；
- 机械臂回差；
- 物料倾斜；
- 松爪后滑动。

因此想拿最高放置分，不能只依赖底盘开到某个坐标。必须有工位近距离视觉、手眼标定和释放前的精定位。

## 2. 总体技术目标

### 2.1 最终比赛能力

系统最终应实现：

1. 支持启停区 1 和启停区 2；
2. 5 秒内一次按键启动；
3. 自动寻找随机二维码板；
4. 严格校验并显示任务码；
5. 自动寻找规定范围内的原料台；
6. 识别红、黄、蓝、绿四种颜色；
7. 判断转盘停止并按顺序抓取；
8. 识别粗加工区和暂存区的三个圆环；
9. 明确区分 1、2、3 号位置；
10. 在灰色可通行区域内规划路径；
11. 检测 φ50×100 mm 黑色障碍物；
12. 障碍物改变后重新规划；
13. 用 X/Y/航向闭环走点；
14. 用工位视觉完成毫米级局部对准；
15. 自动执行两批全部抓取、放置、回抓和同色码垛；
16. 抓取和放置有成功确认；
17. 计数只在成功确认后增加；
18. 最后确认机器人完整外廓进入正确启停区；
19. 典型运行不超过 150 秒；
20. 任何关键传感器失效时安全停车，不继续盲跑。

| 子系统 | 建议验收目标 |
|---|---:|
| 1 m 纵向重复定位 | 10 次，终点标准差 ≤ 8 mm |

## 3. 总体硬件方案

### 3.1 推荐竞赛配置

| 模块 | 推荐配置 | 作用 |
|---|---|---|
| 主控 | STM32H750 | 实时控制、状态机、通信和安全 |
| 底盘 | 现有四轮 STEP/DIR 麦轮 | 已具备基础移动能力 |
| 航向 | JY901/HWT101 | 航向角与角速度 |
| X/Y 定位 | OPS9 或等效二维位置传感器 | 抑制麦轮打滑导致的累计位置误差 |
| 障碍物主传感器 | 低位二维激光雷达 | 在线建立障碍物地图 |
| 障碍物辅助 | 前向/侧向短距 ToF 或触边保护 | 近距离安全停车 |
| 工位视觉 | MaixCAM | 颜色、原料中心、三圆、局部对准 |
| 二维码 | 独立扫码模块 | 快速稳定读取任务码 |
| 机械臂 | M5 旋转、M6 伸缩、M7 升降 | 极坐标抓放 |
| 夹爪 | 串口舵机 + 柔性防滑指 | 兼容不超过 80 mm、100 g 物料 |
| 载物盘 | 三槽旋转盘 + 回零/槽位传感器 | 满足跨区域运输要求 |
| 限位 | M5/M6/M7 物理限位 | 上电自动寻零 |
| 物料检测 | 夹爪负载或光电，三槽物料检测 | 成功确认与正确计数 |
| 显示 | HMI | 任务码、统计、时间、状态和故障 |
| 电源监测 | 电池 ADC + 欠压阈值 | 低电压降速或禁止启动 |
| 急停 | 独立硬件急停 + PB9 长按 | 软件和硬件双通道 |

### 3.2 为什么推荐增加 X/Y 位置传感器

`Move_perfect.cpp` 能够证明底盘会走，但 STEP 脉冲只代表“命令量”。

麦轮实际移动会受到：

- 滚子变形；
- 轮压差异；
- 地面摩擦；
- 横移滑动；
- 加减速；
- 机械臂负载变化；
- 障碍物绕行；
- 碰撞和轻微卡滞；

影响。只有 IMU 时，车头方向可以准，但车体可能平行地偏离目标几十毫米。

比赛路线长、横移多、工位精度高，因此增加 OPS9、编码器里程计或等效位置反馈的收益远高于继续给每一段添加经验补偿。

### 3.3 如果暂时没有 OPS9

可以分三级实施：

#### A 级：推荐正式方案

```text
OPS9 X/Y
  + IMU航向
  + 步进脉冲预测
  + 工位视觉地标修正
```

#### B 级：过渡方案

```text
轮端编码器或带反馈电机里程计
  + IMU
  + 光流
  + 工位视觉重定位
```

#### C 级：最低成本高风险方案

```text
步进脉冲累计
  + IMU
  + 每个工位视觉重定位
  + 多个场地边界/地标校正
```

C 级可以完成联调，但对障碍物绕行和长距离累计误差不够稳，不建议作为最终正式方案。

### 3.4 障碍物传感器选择

黑色障碍物直径只有 50 mm、高度 100 mm，检测并不简单。

#### 推荐：低位二维激光雷达

安装扫描平面建议低于 100 mm，使激光平面能打到障碍物柱体。

优点：

- 直接得到二维距离点；
- 能同时看多个障碍物；
- 易加入占据栅格；
- 不依赖障碍物颜色；
- 能用于墙边、工位边缘辅助定位。

风险：

- 安装高度不对会从障碍物上方扫过；
- 黑色表面可能降低部分雷达回波；
- 需要验证最小物体和最远有效距离；
- 电机振动可能污染扫描。

#### 低成本备选：多路测距 + 前视视觉

至少配置：

- 前中、前左、前右三路；
- 左右侧各一路；
- 前视相机检测黑色柱体。

但必须实测 ToF 对黑色材料的回波。不能只在白墙前测试后就认定可靠。

#### 不建议单独依赖

- 单个正前方超声波；
- 单个红外测距；
- 仅根据电机堵转判断；
- 仅根据黑色像素判断。

φ50 圆柱可能让超声波斜反射，黑色表面可能让红外测距失效，单一通道风险过高。

### 3.5 传感器安装建议

#### 工位相机

- 视轴尽量垂直目标平面；
- 刚性安装，不能随振动改变外参；
- 视野覆盖三个圆环或至少覆盖中心圆与相邻圆；
- 机械臂动作时不得被夹爪完全遮挡；
- 灯光固定在相机附近，减少场地光变化；
- 加偏振片或遮光罩视实物反光情况决定。

#### 雷达

- 扫描面低于障碍物顶部；
- 避开轮子、机械臂和线缆遮挡；
- 明确雷达坐标到车体坐标的外参；
- 安装位置必须计入车体完整外廓。

#### OPS9/光流

- 与地面距离固定；
- 避开机械臂遮挡；
- 远离强振动源；
- 建立传感器坐标到车体坐标变换；
- 用实车快速横移和原地旋转测试。

#### 限位开关

- 优先使用常闭接法，断线时表现为故障；
- 机械端仍应有物理止挡；
- 限位触发后不能继续高速顶住；
- 寻零需要“快速找开关 → 退回 → 慢速二次触发”。

## 4. 坐标系和统一几何模型

### 4.1 世界坐标

建议固定：

```text
场地左下角为 (0,0)
+X 向东
+Y 向北
θ 逆时针为正
```

所有站点、启停区、障碍物和机器人位姿都用这一坐标。

### 4.2 车体坐标

重新定义一个与运动学库一致的车体坐标：

```text
+x_body：实际定义的车体前方
+y_body：车体左侧
+z_body：向上
```

不要在新架构中继续同时使用：

- “新车头”；
- “旧库 forward”；
- “SIDE_12/SIDE_34”；
- “世界东/西/南/北”；

四套互相转换的说法。

可以在底层保留轮号和电机符号，但上层统一只使用：

```cpp
driveBody(vx, vy, wz)
goToPose(x, y, heading)
```

### 4.3 相机坐标

相机坐标至少需要定义：

```text
u：图像向右
v：图像向下
Zc：相机光轴
```

通过相机内参、畸变和外参，把像素点转换到：

- 车体坐标；
- 机械臂基座坐标；
- 工位平面坐标。

不要只用散落在代码中的正负号判断方向。

### 4.4 机械臂坐标

M5/M6/M7 组成近似极坐标机械臂：

```text
M5：平面旋转 θ_arm
M6：径向伸长 r
M7：竖直高度 z
```

已知目标在机械臂基座坐标中的位置 `(x_a,y_a,z_a)`，基础逆解：

```text
θ_arm = atan2(y_a, x_a)
r_target = sqrt(x_a² + y_a²)
M6 = r_target - r_zero
M7 = z_a - z_zero
```

实际还要加入：

- M5 零位偏差；
- M6 零长度；
- 夹爪中心偏移；
- 结构挠度；
- 正反方向回差；
- 不同负载下的高度补偿。

### 4.5 工位坐标

每个工位建立局部坐标：

```text
u：沿三个圆环排列方向
v：垂直工位边界、指向场地内部
w：向上
```

三环名义中心：

```text
u = -150, 0, +150 mm
v = 台面深度中心附近
```

1、2、3 号的方向由规则中“数字面向赛场中心”确定，不能简单把图像左边永久定义为 1 号。

## 7. 位姿估计方案

### 7.1 预测与观测

位姿估计器不应把某一个传感器当作永远正确。

建议：

```text
预测：
  步进命令或轮端编码器

航向观测：
  JY901/HWT101

位置观测：
  OPS9 / 光流 / 轮式里程计

地标观测：
  二维码板、原料台、粗加工台、暂存台视觉
```

### 7.2 第一版可以不急着上完整 EKF

建议开发顺序：

#### 第 1 版

- 脉冲或编码器积分 X/Y；
- IMU 完全接管航向；
- OPS9 对 X/Y 做低通更新；
- 检查跳变、速度上限和数据新鲜度；
- 到工位后用视觉结果修正世界位姿。

#### 第 2 版

- 扩展状态为 `[x,y,θ,vx,vy,imuBias]`；
- 使用 EKF 或误差状态滤波；
- 为每个传感器配置测量噪声；
- 根据传感器健康动态调整权重。

不要一开始为了形式完整直接写复杂 EKF，却没有先测出各传感器真实噪声。

### 7.3 传感器数据准入

每个观测进入融合前检查：

- 时间戳是否新鲜；
- 数值是否有限；
- 单帧跳变是否超过物理可能；
- 推算速度是否超过底盘上限；
- 航向是否发生不合理跳变；
- 连续丢帧次数；
- 传感器自报状态；
- 与其他传感器差异是否持续扩大。

例如 OPS9 单帧跳 300 mm，不能直接覆盖当前位姿。

### 7.4 起点初始化

启动前由抽签选择 `Start1` 或 `Start2`。

机器人按规定边界摆放后：

1. 使用启停区几何设置初始 X/Y；
2. 读取稳定 IMU 并设置本轮航向零点；
3. 如有向下边线传感器，检查实际摆放；
4. 如果摆放与预期误差过大，HMI 显示 `START_POSE_ERROR`，拒绝启动；
5. 5 秒规则要求下，所有初始化必须在裁判指令前的待机阶段完成；
6. 指令发出后按键只负责从 `ARMED` 进入 `RUNNING`。

### 7.5 工位重定位

到二维码、原料、粗加工、暂存工位时：

```text
全局定位把车送到工位附近
  → 视觉检测工位基准
  → 计算车体相对工位误差
  → 小范围闭环修正
  → 用已知工位世界坐标更新 PoseEstimator
```

这样每个工位都是消除累计误差的锚点，而不是只在当前动作时临时修一下。

## 8. 底盘控制方案

### 8.1 保留已有底层，重做上层接口

`Move_perfect.cpp` 中已经验证的四轮运动学、脉冲方向和 IMU 航向处理，可以重构为：

```cpp
class BaseDrive {
public:
  void begin();
  void setBodyVelocity(float vx, float vy, float wz);
  void stop();
  void emergencyStop();
  void service();
};
```

上层不再直接命令某一轮走多少脉冲。

### 8.2 世界坐标位置控制

目标位姿：

```text
目标 (x_t, y_t, θ_t)
当前 (x, y, θ)
```

世界误差：

```text
ex = x_t - x
ey = y_t - y
eθ = wrap(θ_t - θ)
```

转换到车体坐标：

```text
ex_body =  cosθ × ex + sinθ × ey
ey_body = -sinθ × ex + cosθ × ey
```

控制器输出：

```text
vx = PIDx(ex_body)
vy = PIDy(ey_body)
wz = PIDθ(eθ)
```

再进入麦轮逆运动学。

### 8.3 速度曲线

不要只分“高速”和“低速”两档。

建议按剩余距离连续减速：

```text
远距离：允许较高巡航速度
进入减速距离：按距离降低目标速度
接近目标：最小稳定速度
进入位置容差：速度归零
持续稳定一段时间：到点
```

同时限制：

- 最大速度；
- 最大加速度；
- 最大加加速度；
- 携带 3 个物料时的速度；
- 机械臂展开时的速度；
- 障碍物附近的速度；
- 工位附近的速度。

### 8.4 到点判定

不能只判断一次进入误差范围。

建议：

```text
位置误差 ≤ positionTolerance
航向误差 ≤ headingTolerance
实际速度 ≤ velocityTolerance
连续保持 stableTime
```

普通路点与工位路点使用不同容差。

### 8.5 旋转安全

机器人转向时使用完整旋转包络：

```text
旋转半径 = 机器人完整外廓四角到旋转中心的最大距离
```

只有地图中该圆形包络完全位于灰色可通行区且不与障碍物相交，才允许原地转向。

如果空间不足：

- 先移动到安全转向区；
- 或保持当前朝向使用麦轮横移；
- 不能在边界附近强行原地转 180°。

## 9. 地图和路径规划

### 9.1 可通行区域地图

建立 2400×2400 mm 地图。

推荐栅格分辨率：

```text
20 mm/格
```

对应：

```text
120 × 120 = 14400 个栅格
```

STM32H750 可以承担这一规模的 A*。

静态地图包含：

- 灰色允许区域；
- 淡黄色禁区；
- 场地外边界；
- 粗加工台、暂存台、原料台实体；
- 启停区；
- 已知不可进入区域；
- 安全转向区域。

### 9.2 不要只规划车心点

路径规划需要考虑机器人矩形外廓。

为了降低计算量，比赛路径尽量保持四个主航向：

```text
0°、90°、180°、270°
```

针对每个主航向预计算一张“车心可通行地图”：

- 用当前朝向下的矩形外廓对禁区做膨胀；
- 再加入安全余量；
- 障碍物出现后更新对应膨胀区域。

规划状态可以是：

```text
(xGrid, yGrid, headingIndex)
```

允许动作：

- 向前、向后；
- 横移；
- 在安全区转 90°；
- 必要时转 180°；

这样比用一个过大的外接圆膨胀所有方向更容易通过 400 mm 车道，也比完全忽略车体方向安全。

### 9.3 全局路线图

上层任务只指定目标站：

```text
Start → QR → Raw → Process → Storage
                      ↑          │
                      └──────────┘
Storage → Raw → Process → Storage → Start
```

`RoutePlanner` 根据当前启停区和障碍物生成实际路径。

不要为启停区 1 和启停区 2 各复制一份完整任务代码。

### 9.4 障碍物在线更新

雷达或测距得到障碍物后：

1. 从传感器坐标转换到车体坐标；
2. 再转换到世界坐标；
3. 多帧聚类，识别 φ50 柱体；
4. 写入占据地图；
5. 加入障碍物半径与安全距离；
6. 检查当前路径是否仍可通行；
7. 不可通行时减速停车；
8. 从当前位姿重新 A*；
9. 生成新路径后继续。

### 9.5 障碍物不能只看一帧

建立障碍物轨迹：

- 至少连续若干帧出现；
- 世界位置一致；
- 点云尺寸符合可能障碍物；
- 排除机器人自身结构；
- 排除固定工位边缘；
- 排除瞬时噪声。

但近距离安全停车不能等太多帧。采用双层逻辑：

```text
近距离任意可信回波 → 立即减速/停车
多帧确认 → 更新地图并重新规划
```

### 9.6 停车距离

安全监督器实时计算：

```text
制动距离 = v² / (2a_brake) + v × 系统延迟 + 余量
```

障碍物距离小于制动距离时，不允许继续保持当前速度。

系统延迟包括：

- 传感器帧周期；
- 串口传输；
- 数据处理；
- 控制周期；
- 步进电机减速响应；
- 麦轮打滑。

## 10. 随机二维码板搜索

### 10.1 二维码读取分工

推荐独立扫码模块负责解码，MaixCAM 或测距负责确定相对位置。

这样：

- 二维码模块只做它擅长的码内容读取；
- 主控负责验证格式；
- 不需要用通用视觉同时承担所有任务。

### 10.2 搜索策略

二维码板位于右侧规定范围内，不能只走到固定 Y 后无限等待。

推荐：

1. 根据起点规划到右侧二维码搜索走廊；
2. 车体与右边界保持安全距离；
3. 使用侧向测距或板框视觉保持距离；
4. 沿允许的 Y 范围低速扫描；
5. 扫码器持续读取；
6. 有效码到达后立即停车；
7. 记录二维码板实际世界位置；
8. 把该位置作为一次地图地标；
9. 规划前往原料区。

### 10.3 任务码校验

必须检查：

- 总长度 15；
- 三个 `+` 位置正确；
- 颜色只允许 1～4；
- 每批三种颜色不重复；
- 两批颜色集合符合现场物料规则；
- 两个位置组三位均为 1、2、3 的排列；
- 接收缓存无溢出；
- 完整帧结束符；
- 重复读取的有效码一致。

建议连续读到两次相同有效码再最终锁定；若扫码模块本身输出一次很稳定，可将第二次读取作为快速复核，不要显著增加时间。

### 10.4 HMI 显示

任务码锁定后立即完整显示，后续不得被普通状态文本覆盖。

可分两行，但必须保证 15 字符可完整还原。

### 11.2 视觉工作模式

建议：

| 模式 | 功能 |
|---:|---|
| 0 | 停止/空闲 |
| 1 | 红色物料 |

| 8 | 放置后复核 |
| 9 | 启停区/边线 |
| 10 | 标定模式 |

### 11.3 视觉通信协议

不建议继续只回：

```text
x,y
```

推荐二进制帧：

```text
Header
ProtocolVersion
MessageType
RequestSequence
PayloadLength
Payload
CRC16
Tail
```

目标响应至少包含：

```text
mode
sequence
status
targetId
x
y
radius/size
confidence
timestamp
```

状态至少区分：

- `OK`；
- `NO_TARGET`；
- `MULTI_TARGET`；
- `UNSTABLE`；
- `OUT_OF_RANGE`；
- `CALIBRATION_INVALID`；
- `CAMERA_ERROR`。

主控只接受与当前请求序号匹配的响应，防止切模式后旧坐标被误用。

### 11.4 四颜色检测

推荐主方法：

```text
固定曝光/增益/白平衡
  → LAB颜色分割
  → 形态学去噪
  → 连通域
  → 尺寸、形状、位置筛选
  → 颜色统计复核
  → 置信度
```

从 2025 代码借鉴：

- 每种颜色独立阈值；
- 屏幕或维护模式现场调参；
- 阈值持久化；
- 有限范围自适应；
- 目标丢失状态；
- 离群值和低通滤波。

不能直接照搬 2025 三颜色数组，必须支持：

```text
1红、2黄、3蓝、4绿
```

黄色和绿色在不同光照下需要重点测试。

### 11.5 原料目标稳定判断

原料转盘会转动并随机停止。

相机端和主控端双层判断：

#### 相机端

- 连续跟踪同一颜色和同一目标；
- 目标中心移动速度低于阈值；
- 目标轮廓尺寸稳定；
- 连续若干帧保持。

#### 主控端

- 响应序号连续；
- 坐标时间戳新鲜；
- 目标 ID 一致；
- 位置跨度小于阈值；
- 稳定持续时间达到要求；
- 机械臂目标在可达范围内。

只有双方都认为稳定才抓取。

### 11.6 多个同色物料

现场每种颜色可能有两件。

视觉不能只说“找到了红色”，还要选择当前最适合抓取的一件：

- 位于机械臂可达区域；
- 与其他物料不重叠；
- 轮廓完整；
- 抓取中心清晰；
- 置信度最高；
- 未被标记为已经抓取。

抓取后建立短期目标黑名单，防止掉料或残影造成重复选择。

### 11.7 三圆整体识别

粗加工区和暂存区不要只找最近圆。

流程：

1. 检测所有候选圆或椭圆；
2. 按半径、边缘质量筛选；
3. 寻找三个近似共线的圆；
4. 检查相邻间距接近 150 mm；
5. 检查最外两圆间距接近 300 mm；
6. 检查三个半径接近；
7. 根据工位方向和世界坐标排序；
8. 输出 1、2、3 号圆；
9. 如果身份不唯一，返回 `MULTI_TARGET`，不能猜。

### 11.8 是否需要 OCR 识别数字

推荐两层：

- 主要依靠工位世界方向和三圆几何排序；
- 维护/复核模式可用 OCR 或模板识别 1、2、3。

OCR 不应作为唯一方法，因为数字可能被物料遮挡、角度小或印刷反光。

### 11.9 释放前二次视觉

为冲击最高圆环分，采用两阶段放置：

```text
机械臂先到目标上方安全高度
  → 相机重新看目标圆
  → 修正手眼误差
  → 慢速下降
  → 松爪
  → 等待物料稳定
  → 抬爪
  → 视觉复核
```

底盘负责厘米级到位，机械臂视觉伺服负责最后毫米级。

### 11.10 标定

必须完成：

1. 相机内参；
2. 畸变参数；
3. 相机到车体外参；
4. 相机到机械臂基座外参；
5. 夹爪中心相对理论末端偏移；
6. 不同 M7 高度下的像素到毫米关系；
7. M5/M6 不同姿态的回差；
8. 光照和白平衡配置；
9. 标定文件版本和 CRC。

若相机与目标平面高度固定，可以使用单应性；高度变化时需要分高度标定或完整投影模型。

## 12. 原料区方案

### 12.1 找到原料台

全局规划把车送到上边原料区附近，但原料台 X 可能变化。

推荐：

1. 到原料区搜索走廊；
2. MaixCAM 检测直径约 300 mm 的转盘轮廓或三个 120° 物料点；
3. 求转盘中心；
4. 结合场地上边界测距；
5. 修正车体工作位姿；
6. 用该中心更新原料台世界位置。

### 12.2 每件物料抓取流程

```text
请求任务颜色
  → 找到可抓取目标
  → 判断转盘停止
  → 计算机械臂目标
  → 机械臂到预抓高度
  → 二次视觉确认
  → 下探
  → 闭合夹爪
  → 抓取成功检测
  → 提升并缩回
  → 放到指定载物盘槽
  → 载物盘槽位检测
  → 抓取计数+1
  → 下一个任务颜色
```

### 12.3 抓取失败

规则允许当前抓取动作失败后抓下一件，但时间继续。

推荐策略：

- 第一次失败且剩余时间充足：对同色目标重试一次；
- 第二次失败：记录该物料失败，进入下一任务；
- 不允许无限重试；
- HMI 显示失败数；
- 统计“正确抓取数”不增加；
- 如果物料还夹在爪中但未上车，禁止离开本区域。

### 12.4 原料区底盘是否移动

优先让机械臂在可达范围内完成抓取。

如果目标超出机械臂可达范围：

- 只允许在原料区域内做小范围底盘视觉伺服；
- 每次移动前确保机械臂抬高并缩回；
- 移动后重新定位转盘；
- 不允许带着物料悬在夹爪中移动到底盘下一站。

## 13. 粗加工区方案

### 13.1 工位定位

```text
全局走点到粗加工区前
  → 识别台面和三圆
  → 确认1/2/3身份
  → 修正底盘到工作位姿
  → 用三圆中心更新世界位姿
```

### 13.2 第一阶段：放置三件

按当前批次位置组：

1. 载物盘转到当前物料槽；
2. 机械臂从槽位抓起；
3. 抓取成功确认；
4. 转到目标圆环上方；
5. 释放前视觉精定位；
6. 慢速下降；
7. 松爪；
8. 视觉复核物料是否落在目标环；
9. 放置成功才增加放置计数；
10. 处理下一件。

### 13.3 第二阶段：按顺序抓回

三件全部完成放置尝试后：

1. 按规则要求的搬运顺序；
2. 从目标环抓起；
3. 成功确认；
4. 放回对应载物盘槽；
5. 槽位物料存在确认；
6. 抓取计数增加；
7. 三件处理结束后离站。

### 13.4 放置精度分级

视觉复核可以估计物料中心相对圆环中心的偏差，并在 HMI/日志中记录：

```text
预计1环
预计2环
预计3环
……
圆环外
```

这不能代替裁判评分，但可以帮助调参。

如果放置后物料明显倾倒或超出圆环：

- 剩余时间充足且抓取安全时，可以重抓并重放一次；
- 否则记录失败继续；
- 不应为一件物料耗尽整场时间。

## 14. 暂存区与同色码垛方案

### 14.1 第一批

第一批暂存位置直接使用第一批位置组。

放置目标：

- 1、2、3 号环身份正确；
- 平面放置；
- 物料稳定；
- 为第二批码垛保留姿态。

第一批每次放置后记录：

```text
颜色 → 暂存环号
```

### 14.2 第二批位置计算

例如：

```text
任务码：134+123+314+231
```

第一批：

```text
颜色1 → 暂存1号
颜色3 → 暂存2号
颜色4 → 暂存3号
```

第二批暂存：

```text
颜色3 → 叠到第一批颜色3所在的2号
颜色1 → 叠到第一批颜色1所在的1号
颜色4 → 叠到第一批颜色4所在的3号
```

第四组 `231` 只决定第二批粗加工区位置，不决定最终暂存码垛位置。

### 14.3 码垛视觉

第二批码垛不能只使用固定高度。

推荐检测：

- 底层物料中心；
- 底层物料顶部轮廓；
- 目标颜色；
- 当前堆叠是否稳定；
- 上层释放后的偏移和倾斜。

码垛流程：

```text
找到第一批同色底层
  → 到底层中心上方
  → 视觉确认颜色与位置
  → 慢速下降到码垛高度
  → 低冲击松爪
  → 等待稳定
  → 抬爪
  → 视觉复核
```

### 14.4 防倒措施

机械方面建议：

- 夹爪指端等高；
- 松爪对称；
- 物料中心与夹爪中心一致；
- M7 下降垂直；
- 释放速度低；
- 爪指表面不粘连物料；
- 载物盘运输时减少物料倾斜。

软件方面：

- M5/M6 到位后等待短暂稳定；
- M7 低速完成最后 10～20 mm；
- 松爪后保持机械臂不动短暂观察；
- 复核稳定后再抬升。

## 15. 机械臂控制方案

### 15.1 上电寻零

上电流程：

```text
夹爪打开
  → M7向上找限位
  → 退回
  → M7慢速二次找零
  → M6向内找限位
  → 退回
  → M6慢速二次找零
  → M5找基准开关
  → 退回
  → M5慢速二次找零
  → 载物盘找零
  → 全部零点有效
  → 系统进入ARMED
```

寻零在裁判开始指令前完成。

任一轴寻零失败，不允许正式启动。

### 15.2 通用搬运状态机

所有搬运复用：

```text
OpenGripper
  → LiftSafe
  → RetractSafe
  → RotateSource
  → ExtendSource
  → DescendSource
  → CloseGripper
  → VerifyGrip
  → LiftLoaded
  → RetractLoaded
  → RotateDestination
  → ExtendDestination
  → VisualFineAlign
  → DescendDestination
  → OpenGripper
  → VerifyRelease
  → LiftSafe
  → RetractSafe
  → ReturnStandard
```

每一步都有：

- 开始时间；
- 目标位置；
- 当前反馈；
- 超时；
- 行程限制；
- 故障码；
- 中止动作。

### 15.3 安全动作顺序

机械臂转动前：

- M7 必须在安全高度；
- M6 必须缩回到安全范围；
- 夹爪状态已知；
- 底盘速度为零。

底盘离站前：

- M7 已抬高；
- M6 已缩回；
- M5 在运输姿态；
- 当前物料已放到载物盘；
- 载物盘槽位锁定。

### 15.4 夹爪结构

物料形状在决赛现场可能变化，但尺寸不超过 80 mm、重量不超过 100 g。

推荐：

- 指端带柔性防滑层；
- 入口做导向斜面；
- 开口覆盖最大物料；
- 夹紧力可调；
- 左右爪同步；
- 不对薄壁或锥体施加过大力；
- 夹爪负载或电流可读；
- 有“空闭合角”和“夹住物料角”标定。

### 15.5 抓取成功判断

建议融合：

```text
夹爪闭合角
  + 舵机负载/电流
  + 夹爪内光电
  + 抓后视觉
```

至少两个条件一致才判成功。

### 15.6 载物盘

三槽载物盘需要：

- 独立零位；
- 三个槽位角标定；
- 到位反馈或编码器；
- 每槽物料存在传感器；
- 防止加速时物料滑出；
- 槽位与机械臂抓取中心重复精度高。

载物盘可以在机械臂安全缩回期间提前转到下一槽位，节省时间。

## 16. 比赛任务状态机

### 16.1 顶层状态

```text
BOOT
  → SELF_TEST
  → HOMING
  → CALIBRATION_READY
  → ARMED
  → STARTING
  → QR_SEARCH
  → QR_DECODE
  → RAW_BATCH_1
  → PROCESS_UNLOAD_1
  → PROCESS_RELOAD_1
  → STORAGE_PLACE_1
  → RAW_BATCH_2
  → PROCESS_UNLOAD_2
  → PROCESS_RELOAD_2
  → STORAGE_STACK_2
  → RETURN_START_ZONE
  → FINAL_ZONE_ALIGN
  → FINISHED
```

任意运行状态可进入：

```text
RECOVERY
FAULT
EMERGENCY_STOP
TIME_BUDGET_RETURN
```

### 16.2 启动前自检

必须在进入 `ARMED` 前通过：

- IMU 数据新鲜；
- X/Y 定位有效；
- 雷达或障碍物传感器有效；
- MaixCAM 在线且版本正确；
- 二维码串口在线；
- M5/M6/M7 已寻零；
- 夹爪在线；
- 载物盘在线并回零；
- HMI 在线；
- 电池电压足够；
- 启停区配置已选择；
- 参数 CRC 正确；
- 急停未按下。

### 16.3 一键启动

裁判指令前系统已经处于 `ARMED`。

按下唯一启动键后：

1. 锁定启停区和参数；
2. 清空本轮计数；
3. 启动 180 秒比赛计时；
4. 保存日志起点；
5. 在 5 秒内开始移动；
6. 后续按键不允许重新开始本轮。

### 16.4 每个任务状态的统一接口

```cpp
class MissionStep {
public:
  void start();
  void service();
  ActionResult result() const;
  void abort();
};
```

顶层只根据 `ActionResult` 推进，不直接控制电机和舵机。

### 16.5 失败后的继续策略

分为：

#### 可重试

- 单帧视觉丢失；
- 第一次抓取失败；
- 圆环定位置信度低；
- 短时 OPS9 丢帧；
- 临时路径被障碍物阻挡。

#### 可跳过

- 某一物料连续抓取失败；
- 某次放置无法安全重做；
- 剩余时间不足以继续一个完整动作。

#### 必须故障停车

- IMU 持续失效；
- X/Y 位姿不可信且无法地标恢复；
- 雷达与近距安全传感器同时失效；
- 机械臂未寻零；
- M6/M7 堵转；
- 夹爪夹着物料却无法安全放置；
- 急停；
- 机器人可能进入非灰色区域。

## 17. 时间预算和比赛策略

### 17.1 动作数量

完整流程需要 24 次“源到目标”的物料搬运：

```text
原料区抓到车载盘：6次
粗加工区车载盘放到圆环：6次
粗加工区圆环抓回车载盘：6次
暂存区车载盘放置/码垛：6次
```

机械臂时间是总时长最大的部分之一。

### 17.2 建议时间预算

| 项目 | 目标时间 |
|---|---:|
| 启动与二维码 | 5～8 s |
| 全部底盘跨区移动 | 30～38 s |
| 6次原料抓取 | 22～26 s |
| 12次粗加工放/抓 | 38～45 s |
| 6次暂存放置/码垛 | 20～24 s |
| 四个圆工位视觉对准 | 8～12 s |
| 最终回区和确认 | 5～8 s |
| 重试/避障余量 | 15～20 s |
| 合计目标 | 143～165 s |

这要求单次机械搬运平均约 3～4 秒，需要：

- M5/M6/M7 合理提高速度；
- 安全动作并行；
- 载物盘提前转位；
- 视觉请求提前开始；
- 减少不必要的回零；
- 但不能取消必要的安全抬高和缩回。

### 17.3 剩余时间监督

`TimeBudgetManager` 实时维护：

```text
elapsed
remaining
currentStepEstimate
returnToZoneEstimate
safetyMargin
```

规则：

```text
如果 remaining < returnToZoneEstimate + safetyMargin
  → 停止开始新的物料动作
  → 收好机械臂
  → 返回抽签启停区
```

建议安全余量至少 8～12 秒。

即使未完成全部任务，已经完成的抓取、放置和正确返回仍可能有价值。比在最后一个工位超时、没有返回更合理。

### 17.4 两次运行机会

两次运行机会建议：

- 第一轮使用稳定参数，优先获得完整有效成绩；
- 记录每一段耗时、视觉重试和位置误差；
- 第二轮调试时间内只修改有证据的问题；
- 不在第二轮临时重写路线逻辑；
- 可在 HMI 预先选择 `STABLE` 或 `FAST` 参数档，但运行开始后锁定。

## 18. 安全监督与故障恢复

### 18.1 SafetySupervisor 最高优先级

任何模块发出的移动命令都必须经过安全监督：

```text
目标速度
  → 场地边界检查
  → 障碍物制动距离检查
  → 机械臂运输姿态检查
  → 位姿可信度检查
  → 电池和驱动状态检查
  → 最终下发
```

### 18.2 统一故障动作

严重故障：

1. 底盘速度立即降为零；
2. 停止产生新路径；
3. 停止机械臂新动作；
4. 如果安全，抬高并缩回机械臂；
5. 如果不能安全收臂，保持当前；
6. 停止相机主动动作请求；
7. 锁定本轮不能重启；
8. HMI 显示故障码；
9. 日志保存故障前后的关键数据。

### 18.3 分层超时

| 对象 | 必须监控 |
|---|---|
| 单段路径 | 预计时间 + 余量 |
| 底盘到点 | 最大总时间、最大振荡次数 |
| 单次转向 | 最大时间、最大修正次数 |
| 障碍物重规划 | 最大计算时间、无路可走 |
| 视觉首帧 | 首帧超时 |
| 视觉连续帧 | 帧间超时 |
| 单个目标搜索 | 最大搜索时间和距离 |
| 单个机械臂阶段 | 独立超时 |
| 单次搬运 | 总超时 |
| 单个工位 | 总超时 |
| 整场 | 180 秒 |
| 长时间无状态推进 | 预警和恢复 |

### 18.4 防止长时间不动

补充解析资料提示机器人 15 秒没有移动可能结束本轮。

因此：

- 视觉等待不能无限；
- 状态机 8～10 秒没有进展应报警；
- 能做安全搜索时进入小范围搜索；
- 无法安全恢复时立即执行返回或故障策略；
- 不能为了“避免15秒”无目的乱动，所有动作仍必须安全且符合规则。

### 18.5 边界保护

每次路径跟踪前预测未来短时间的机器人矩形外廓。

如果外廓将进入非灰色区域：

- 立即限制速度；
- 重新规划；
- 位姿不可信时停车；
- 不允许以“传感器可能误差”为理由继续赌路线。

## 19. HMI 设计

### 19.1 比赛主页

## 23. 主要风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 麦轮横移打滑 | 工位位置累计漂移 | X/Y反馈 + 工位地标重定位 |
| OPS9跳变 | 车辆突然偏航或偏移 | 数据准入、创新门限、降级 |
| 黑色障碍物回波弱 | 漏检碰撞 | 雷达实测 + 近距辅助 + 视觉 |
| 车宽与道路余量小 | 路径不可通过 | 矩形外廓规划、备用道路、禁止盲绕 |
| 黄色与高光混淆 | 抓错颜色 | 固定曝光、LAB、几何复核、数据集 |
| 三圆编号颠倒 | 整批放错位置 | 三圆整体几何 + 世界方向 + 身份置信度 |
| 第一环精度极高 | 放置低分 | 手眼标定、释放前二次视觉、低速释放 |
| 物料形状现场变化 | 夹取失败 | 柔性夹爪、负载检测、维护标定 |
| 机械臂无物理零点 | 撞机构 | 三轴限位和自动寻零 |
| 计数与事实不符 | 显示统计失分 | 成功检测后才计数 |
| 视觉等待过久 | 超时或长时间不动 | 首帧/总超时、有限搜索、时间监督 |
| 24次搬运动作过慢 | 超过3分钟 | 动作并行、速度标定、时间预算 |
| 最终只看车心 | 车体未完全入区 | 完整外廓判定 + 边线/视觉确认 |
| 两个启停区逻辑复制 | 修改遗漏 | 参数化站点和统一规划 |
| 主程序过大 | 难维护、难测试 | 模块化和接口化 |

## 25. 建议现在立即开始的工作

按照收益和依赖关系，建议下一步不是继续写完整比赛主程序，而是依次完成：

1. **测量并冻结机器人完整外廓、机械臂偏移和三个轴行程。**
2. **把 `Move_perfect.cpp` 的底盘、IMU 抽成独立模块。**
3. **确定 X/Y 位置反馈硬件，优先 OPS9 或等效方案。**
4. **完成 `PoseEstimator`，先只显示和记录，不立刻控制。**
5. **实现 `goToPose(x,y,θ)`，用四点方形路线验收。**
6. **建立 2026 灰色可通行地图和车体外廓碰撞检查。**
7. **确定障碍物传感器，先完成“检测即停”。**
8. **独立建立 MaixCAM 仓库，实现四颜色和三圆整体识别。**
9. **给 M5/M6/M7 增加物理寻零。**
10. **先完成一件物料的“视觉抓取 → 上车 → 圆环放置 → 抓回”。**
11. **再扩展到三件、两批和同色码垛。**
12. **最后接入顶层比赛状态机和 3 分钟时间策略。**

最关键的三个技术验证是：

```text
验证1：底盘能否在打滑后仍闭环到世界坐标点
验证2：视觉和机械臂能否把物料中心放到圆环中心的毫米级范围
验证3：机器人能否在随机障碍物下保持完整外廓只走灰色区域
```

这三个验证通过，整场流程主要是任务编排；如果三个验证没有通过，继续添加固定路线补偿只会让程序越来越难维护。

## 26. 最终定义

这份从零方案的最终系统应当是：

> 一套以 `Move_perfect` 已验证的底盘运动能力为起点，以 X/Y/航向闭环为全局导航基础，以地图和障碍物重规划适应随机赛场，以 MaixCAM 和手眼标定完成工位毫米级操作，以非阻塞机械臂状态机完成 24 次物料搬运，并用成功传感器、时间预算和完整外廓检查保证评分真实性与比赛安全的 2026 浙江省赛搬运机器人。

它与“把固定路线全部写进一个 main.cpp”最大的区别是：

```text
固定路线写法：
  希望实际赛场与调试场完全相同

本方案：
  测量当前在哪里
  感知前方有什么
  根据抽签和障碍物决定怎么走
  到工位后再精确测量
  动作成功后才进入下一步
```

因此，本方案更适合作为后续完整工程的架构基线。
