# 2026-11-19 整体软件仿真与检查报告

结论：实际导航模块在本轮7,418种离散事件场景中没有发出违反独立几何约束的导航动作，
没有检测到ASan/UBSan错误。完整任务完成率明显低于两点寻路率，主要受固定扫描准备、
必经目标整格禁行和道路断开影响。全部12个固件环境构建通过。当前正式测试38项，29通过、
9项既有失败；不能宣称全部测试通过。

本轮只增加测试与报告，没有修改正式运动、机械臂、视觉或导航实现，没有烧录、提交或推送。
基线仍是e1a285cef19e081a0f6cece95cf8ff5ab72cd12f，测的是该基线加当前工作区已有实现，
不是未修改的11月2日程序。source_fingerprints.json记录实际测试源码SHA-256。

## 仿真范围与证据强度

- 实际编译运行：QimingGrid协议、GridMission、NavigationMode、CompetitionCore、VisionProtocol、
  MecanumOdometry等C++模块；相关原测试还编译执行从正式源码提取的底盘路线、料盘和机械臂函数。
- 导航模拟器的雷达采用独立BFS生成路径，含直线压缩节点；不调用被测GridGeometry::plan生成期望路径。
- 独立几何检查对每个发出的MOVE/TURN检查车身扫掠、黄色实际矩形、整格障碍及场地边界。
  对静态0～3格障碍、首扫有障碍而二扫为空的场景，另用独立任务可达性模型核对完成/拒绝结果。
- 场景中的运动完成、二维码读出、六个工位完成采用离散事件模型，含可配置延迟。
  成功到WORK表示正确触发了工位入口；模拟器没有在每次场景中执行整个机械臂和图像识别流程。
- 未运行STM32整机指令级仿真，也没有真实雷达、驱动器、电机、舵机或MaixCAM图像输入。
  固件构建和模块仿真不能证明打滑、抓放、串口电气、扫描盲区或实车毫米定位正确。
- 模型使用现有290×234 mm车身、5 mm余量和均分480 mm格网。虚拟时间不是实车耗时预测。

## 两区完整导航场景

共7,418种：1,840种完成六工位入口并返回，4种空图交接旧路线，5,574种进入故障状态。
这里的故障状态多数是障碍使当前策略不可执行或刻意注入故障；不是5,574个程序缺陷。
也不能把它们全部解释成任何策略都无解，固定扫描旋转点不够灵活就是策略限制。

| 随机通信/运动/二维码/工位延迟 | 100 | 100 | 0 | 0 |
| 起点X/Y边界摆放 | 18 | 8 | 0 | 10 |

### 静态地图完整任务完成比例

这些枚举平均包含所有21个非永久禁入格，不代表现场障碍分布概率；格数也不等于障碍柱数量。

| 障碍格数 | 每个启停区布局数 | 区1完成 | 区2完成 | 每区完成比例 |
|---|---:|---:|---:|---:|
| 0 | 1 | 空图交接 | 空图交接 | 交接通过，后续由旧路线测试验证 |
| 1 | 21 | 14 | 14 | 66.67% |
| 2 | 210 | 91 | 91 | 43.33% |
| 3 | 1330 | 319 | 319 | 23.98% |

静态地图共2,274次拒绝：422次首段移动不安全，726次扫描旋转位置净空不足，
1,018次必经目标格被占用，108次当前起终点之间断路。

单障碍格的7种失败，在每个区都可以明确列出：

- 两区共有：2号格（粗加工）、10号格（二维码）、14号格（暂存）、22号格（原料）占用后，
  目标整格禁入；当前程序不在同一格剩余空间内重选停靠点。
- 区1：20号格占用使起步移动不安全；19或21号格占用使固定360°扫描位置不安全。
- 区2：0号格占用使起步移动不安全；1或9号格占用使固定360°扫描位置不安全。

若先排除发车格及四个工位格占用，每区的单/双/三障碍组合完成分别为14/16、91/120、319/560，
即87.50%、75.83%、56.96%。仍不可把这些比例称为实车成功率。

### 本轮明确暴露的两个策略限制

1. 固定扫描位置：区1的(350,2100)、区2的(350,300)靠近邻格。邻格有障碍时旋转圆盘被拒绝，
   即使该布局存在其他安全扫描位置，当前程序也不会重选。此类停止满足安全约束，但降低任务完成率。
2. 首扫空图立即交接：若首次扫描因为遮挡漏掉障碍，程序不会做第二扫来发现它，而是执行旧路线。
   两个专门场景已确认此分支；本轮没有人为把它改成故障或声称它能覆盖漏检。也没有动态障碍保护。

## 独立两点寻路枚举

总计3,905,000次请求，四个正交航向、所有25×25起终点、0～3个额外障碍格的所有组合。
排除起终点占用后，规划成功/合法请求分别为：

| 障碍格数 | 成功/合法请求 | 比例 | 合法请求失败原因 |
|---|---:|---:|---|
| 0 | 1764/1764 | 100% | 无 |
| 1 | 33600/33600 | 100% | 无 |
| 2 | 297224/303240 | 98.0161% | 6016次网格断开 |
| 3 | 1560096/1723680 | 90.5096% | 163584次网格断开 |

这一测试与完整任务不同：只回答两个指定格子之间是否可达，不包含固定起步、扫描、工位进入和返程。
本范围内没有独立连通性判断有路而实际规划器漏找的结果，也没有额外车身净空拒绝。

## 延迟、故障与通信压力

- 108种正常时序场景全部完成：0～500 ms通信延迟，ACK先后交替，分片长度1～31，
  变长运动完成、二维码0～8 s延迟、工位0～2.5 s延迟，部分跨越uint32 millis回绕。
- 两区均验证无HELLO、缺扫描方格结果、扫描溢出、CRC损坏、保存记录不更新、负ACK、
  错误路径请求序号、发送缓冲不可用：全部进入故障，不切换到空图或LEGACY继续走。
- 二维码超时和扫描总时限独立注入，均故障锁定。
- 未公开事件和其他节点错误帧不影响正常任务；首扫有障碍而二扫为空时不会抹去首扫障碍。
- 实际COBS/CRC编解码器通过20,000次随机有效帧往返、20,000次损坏帧拒绝和300,000字节垃圾流恢复，
  ASan/UBSan无报错。随机种子固定为20261119。
- 原有底盘桥接验证IMU丢失、偏航超限、运动超时、360°累计转向和末端稳定检查。

## 复现与原始数据

```sh
python3 test/simulation_suite.py
python3 test/grid_scenarios_test.py --output /private/tmp/gc_scenarios
```

第一条会运行38个脚本和5个原生程序，因九项既有失败返回1，这是保留失败的预期报告行为。
第二条单独运行导航场景，断言通过才返回0。

- grid_scenarios.jsonl：每个场景的两张地图位掩码、区域、退出状态、错误/阶段、工位次数和返回位置。
- grid_summary.json：场景汇总和两区0～3障碍格明细。
- existing_tests.json、native_modules.json、suite_summary.json：各脚本与原生程序完整输出。
- grid_run.json：导航编译命令、退出值和stderr。
- firmware_build.json、firmware_build.log、firmware_sizes.json：构建结果。
- source_fingerprints.json：实际源码校验值。

outcome=1为空图交接，2为六工位入口完成并回原点，3为故障；error对应GridMission错误码。
全量阶段枚举见lib/QimingGrid/src/GridNavigator.h。不是所有outcome=3都代表软件测试失败。
